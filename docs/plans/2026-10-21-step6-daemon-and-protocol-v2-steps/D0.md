## 5. Proposed decisions

### 2026-10-22 · The wire error code is optional and normalised to INTERNAL
**Decided:** The wire error type is `WireError {code?: ErrorCode | string, message, data?}`.
`fromWire` maps a code that is missing, non-string or empty to `INTERNAL`. It keeps any non-empty
string code, including one outside the 22.
**Why:** The unmodified v1 extension sends `{message}` only (spec §10 compatibility; stage0-audit
B6). Keeping unknown codes means a newer peer's code is not lost.
**Instead of:** A required `code`, which describes v1 traffic wrongly; or rejecting unknown codes.
**Revisit if:** Step 7 teaches the extension codes. Then the v2 peers could use a type with `code`
required.
**By:** Claude (proposed)

### 2026-10-22 · isHello rejects malformed v2 hello fields
**Decided:** When `role`, `name`, `build` or `proto` is present, it must be well-typed: `role` is
"extension" or "client", `name` and `build` are strings, and `proto` is a number. Otherwise
`isHello` returns false.
**Why:** This gives D0.4 a test that fails without the change, and it matches D2's "unknown role →
4001". `proto` is a number rather than the literal 2, so a future version reaches the `VERSION`
handling instead of being rejected as a malformed hello.
**Instead of:** Accepting any extra fields, as v1 did.
**Revisit if:** A real client sends a field in another type.
**By:** Claude (proposed)

### 2026-10-22 · New shared modules are exported by subpath and from the root
**Decided:** `shared/package.json` exports `./codes` and `./error`, and `protocol.ts` re-exports
both, so `import { BridgeError } from "@bridge/shared"` works.
**Why:** Required by decisions.md 2026-10-22 #17 (F18). The root re-export keeps the existing
import sites short. The extension imports only types, and its bundle is unchanged.
**Instead of:** Subpath exports only; or a root re-export only.
**Revisit if:** A bundle ends up with two copies of `BridgeError`, which would break `instanceof`.
**By:** Claude (proposed)

### 2026-10-22 · An event requires a params object and carries no id
**Decided:** `isEvent` requires all of the following:
- `event` is a string;
- there is no `id` key;
- `params` is a non-null object.

An emitter with nothing to send passes `params: {}`.
**Why:** Spec §10 writes `{event, params}`, and the missing `id` is what tells an event apart from a
request or a response.
**Instead of:** Making `params` optional.
**Revisit if:** An emitter in D2 or Step 7 needs an event without params.
**By:** Claude (proposed)
