## 5. Proposed decisions

### 2026-10-22 · Until D3 the root build skips the daemon
**Decided:** The root `build` is `npm run build --workspaces --if-present`; `daemon` has no build script
until D3, so only `mcp` and `extension` build, and no `daemon/dist` exists. D3 adds
`"build": "node build.mjs"` to `daemon/package.json` (and fixes `daemon/build.mjs`'s stale "built
server" log line) and the root picks it up unchanged.
**Why:** Measured: a failing workspace makes the command exit 1, and a scriptless one is skipped. It
covers all five workspaces without a per-stage root edit.
**Instead of:** `npm run build -w mcp && npm run build -w extension` (D3 must edit it again); a no-op
daemon build script that prints a message.
**Revisit if:** a build must run in a fixed order other than the `workspaces` array order.
**By:** Claude (proposed)

### 2026-10-22 · @bridge/daemon exports ./connection until D5
**Decided:** `@bridge/daemon` exports `./connection` beside `./bridge`, `./wsHost`, `./startup`, and the
moved `mcp/test/tools.test.ts` imports `@bridge/daemon/connection`.
**Why:** The test builds an `ExtensionConnection` through a dynamic import; changing the specifier keeps
the test logic untouched.
**Instead of:** editing the test (a logic change, outside "moves only"); a deep import of `src/`.
**Revisit if:** D5 drops the `@bridge/daemon` dependency — remove the interim exports with it.
**By:** Claude (proposed)

### 2026-10-22 · The lockfile's stale server entry was removed by hand
**Decided:** The extraneous `packages["server"]` key was deleted from `package-lock.json`, then
`npm install` re-run.
**Why:** npm kept it through `install`, `prune` and a rebuilt hidden lockfile; regenerating the whole
lockfile would bump unrelated versions.
**Instead of:** deleting and regenerating `package-lock.json`.
**Revisit if:** a later `npm install` brings the entry back.
**By:** Claude (proposed)
