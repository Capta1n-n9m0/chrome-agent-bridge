## 4. Deviations from the phase doc

1. **MUX-5 "the script reports 'upgraded daemon'".**
   - The SDK has no such signal: `connect()` gives a client with `welcome`, and `on("reconnected")`
     fires only on a 4002 reconnect.
   - The row is judged on four things: the recipe's `daemon build <new>` with `up 0s` or `up 1s`;
     the new daemon pid; the old daemon's `exit 0 (shutdown 4002)` line; and `build <new>` in
     `browser_status`.
   - The phase doc carries a dated note.
2. **MUX-1 "`Get-Process node`".** Windows PowerShell 5.1's `Get-Process` has no command line, so
   the row uses `Get-CimInstance Win32_Process` (helper `Get-BridgeDaemon`).
3. **MUX-4 "reconnect attempts".** The extension logs no line for an attempt. Each failed attempt
   shows as another `[bridge] connection: down` line.
4. **MUX-3.** A 60 s background hold, so that `browser_status` can see the recipe; a plain run lasts
   under a second.
5. **MUX-7.** Adds (d), a contrast case: a tree kill of a session that did not spawn the daemon. It

## 5. Proposed decisions

### 2026-10-22 · The D6 wave provides the token through `bridge.token` only
- **Decided:** create `bridge.token` at the repo root (gitignored, `.gitignore:16`) with a command
  that prints nothing, and unset `BRIDGE_TOKEN` in the MCP config and the shell for the wave.
- **Why:** every client reads its own environment first, so a mix of sources gives close-4001
  rejections. The file is the one source the MCP, the recipe and the spawned daemon all share.
- **Instead of:** the variable in the MCP config plus `$env:BRIDGE_TOKEN` in every shell.
- **Revisit if:** the user prefers env-only tokens.
- **By:** Claude (proposed).

### 2026-10-22 · `recipes/hello.ts` prints ids and titles, never URLs, and proves the hold survived
- **Decided:** the recipe prints counts, ids and titles only. After a hold it calls `daemon.status`
  again and must find its own client listed; otherwise it prints `FAILED` and exits 1.
- **Why:** URLs can carry tokens and the output becomes evidence. The SDK has no public close event.
- **Instead of:** printing the full `listTabs` result, and importing the internal `onClientFailure`.
- **Revisit if:** Step 8 adds a public close event.
- **By:** Claude (proposed).

### 2026-10-22 · MUX-5 changes the build by appending a comment to `daemon/dist/index.js`
- **Decided:** append a timestamped comment; undo with `npm run build --workspace daemon`, which the
  verifier measured to restore the same hash.
- **Why:** it changes the hash without a source edit, and `dist/` is gitignored.
- **Instead of:** a no-op source edit plus a rebuild.
- **Revisit if:** esbuild output stops being deterministic.
- **By:** Claude (proposed).

### 2026-10-22 · DL-2's cross-origin redirect comes from a stdlib fixture on `127.0.0.1:8081`
- **Decided:** use `redirect_server.py`, which redirects to `localhost:8080`. From the fixture's own
  `/page`, the page can fetch `/page` (200) but not `/dl2` (`TypeError: Failed to fetch`), while
  `browser_download` of `/dl2` succeeds and prints `(followed redirects to localhost:8080)`.
- **Why:** `python -m http.server` cannot redirect across origins. Fetching from the same origin
  isolates the redirect as the cause.
- **Instead of:** an external host, or a cross-origin first hop with a caveat.
- **Revisit if:** Chrome's Local Network Access starts prompting for loopback-to-loopback requests.
- **By:** Claude (proposed).

### 2026-10-22 · The wave may be driven by UI automation; every step is tagged
- **Decided:** every step carries a tag: [UI] for automation, [SH] for an agent's shell, [USER] for
  the user. Ten cautions (A1–A10) say where automation would disturb the measurement.
- **Why:** this is the user's note of 2026-10-22, relayed by the session agent.
- **Instead of:** untagged steps written for a person.
- **Revisit if:** the wave shows a tag was wrong.
- **By:** Claude (proposed).
