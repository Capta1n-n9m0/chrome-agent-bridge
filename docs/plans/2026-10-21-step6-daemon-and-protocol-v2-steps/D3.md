### The daemon as built

- **Env vars:**
  - `BRIDGE_TOKEN`: read through `resolveToken({env})` from `@bridge/sdk/token`. When it is unset, the daemon falls back to `bridge.token` at the workspace root, found by walking up from `daemon/dist`.
  - `BRIDGE_PORT`: default 9234, plain digits 1–65535. Anything else is logged and the daemon exits 1.
  - `BRIDGE_DAEMON_IDLE_MS`: default 600000, plain digits 1–2147483647. Anything else is logged ("…; using 600000") and the default is used.
  - D3 adds no new env var.
- **Log path and writing:**
  - The path is `~/.chrome-agent-bridge/daemon.log` (`os.homedir()`); the directory is created recursively. Tests override the path by injection.
  - Each line is written synchronously with `appendFileSync`.
  - At start, a log over 1 MiB is cut to its last 1,048,576 bytes and then forward to the next newline.
  - A log that cannot be created or written is a silent no-op: it never throws and never writes to stdout or stderr.
- **Log format:** `YYYY-MM-DDTHH:MM:SSZ <message>`. The lines are:
  - `start pid=N`
  - `config pid=N port=P idleMs=M build=<sha256>`
  - `listening on 127.0.0.1:P`
  - `client + "<name>" (N clients)` and `client - "<name>" (N clients)`; the name is JSON-escaped
  - `<why> — shutting down`
  - `port P in use — another daemon owns it`
  - `exit <code> (<why>) clients=… extensionEvents=… ignoredClientFrames=…`
  - `fatal: <ErrorName>`
- **Redaction:** every line goes through `redact`. A line that contains `://` or the token is replaced whole by `[line withheld: contained a URL or the token]`. Fatal errors log only the error's name.
- **Exit codes:**
  - 0: `EADDRINUSE` on the single `listen()`, with no retry. Also every completed shutdown: a signal, the idle timer, or a client's `daemon.shutdown` (4002), all through the `onShutdown` hook.
  - 1: a bad `BRIDGE_PORT`; no token (the log gets resolveToken's message, which names both places and never the value); an entry file that cannot be hashed; any other listen error (only its code is logged); an `uncaughtException` or `unhandledRejection`.
  - The process exits at most once.
- **Signals:** SIGINT, SIGTERM and SIGBREAK log the signal, then `host.shutdown(1001)` (close frames, ≤ 1 s grace, terminate), then exit 0. A second signal is a no-op.
- **Idle:**
  - The timer is armed right after `listen` succeeds, with 0 clients.
  - It is fed only by `registry.onCountChange`, so the extension does not count.
  - When it fires, the daemon calls `host.shutdown(1001)` and then exits 0. It fires at most once.
- **Bind:** `127.0.0.1` only (`WsHost`), exactly once. Tests use port 0, ephemeral ports or a fake host; nothing bound 9234.

## 5. Proposed decisions

### 2026-10-22 · The daemon's idle timer is armed at start
**Decided:** `idle.update(0)` runs right after a successful `listen()`, so a daemon that no client ever reaches exits after `BRIDGE_DAEMON_IDLE_MS`. **Why:** A spawned daemon whose client died before its hello must not live forever. **Instead of:** Arming only on the first drop to 0 clients. **Revisit if:** D6 sees a daemon exit before a slow first client connects. **By:** Claude (proposed)

### 2026-10-22 · Every daemon shutdown exits 0 through one WsHost hook
**Decided:**
- SIGINT, SIGTERM, SIGBREAK and the idle timer call `host.shutdown(1001)`, and `daemon.shutdown` calls `shutdown(4002)`.
- A new `WsHost` option, `onShutdown(code)`, runs once after the first shutdown completes. The daemon exits 0 there for every cause.
- `EADDRINUSE` also exits 0.

**Why:** A detached daemon has no parent reading its exit code. Decision #15 makes `shutdown` the graceful stop. The route calls `shutdown` on the host itself, so only a hook on the host sees the 4002 path.

**Instead of:**
- `host.close()` then exit, as written in decision 0.6 (clients would see 1006);
- exit codes 128+n for signals;
- wrapping the route context.

**Revisit if:** A supervisor needs to tell the causes apart.

**By:** Claude (proposed)

### 2026-10-22 · Daemon env parsing: a bad idle value falls back, a bad port exits 1
**Decided:**
- `BRIDGE_DAEMON_IDLE_MS` must be plain digits from 1 to 2147483647. Otherwise the daemon logs it and uses 600000.
- `IdleTimer` itself throws a `RangeError` outside that range.
- A `BRIDGE_PORT` that is not plain digits from 1 to 65535 is logged, and the daemon exits 1.

**Why:** Above 2^31−1 ms, Node's `setTimeout` fires after 1 ms (verifier finding 1, measured: exit after 133 ms). A wrong idle value is harmless once defaulted. A wrong port gives a daemon that no client can find.

**Instead of:** Exiting on both; clamping either value.

**Revisit if:** The SDK ever passes port 0.

**By:** Claude (proposed)

### 2026-10-22 · The daemon log: fixed path, whole lines, withheld lines, names only for errors
**Decided:**
- The path is `~/.chrome-agent-bridge/daemon.log`, overridable only by injection (tests). There is no `BRIDGE_DAEMON_LOG` env var.
- At start the log is cut to its last 1 MiB and then forward to a whole line.
- A line containing `://` or the token is replaced whole by a fixed placeholder.
- Fatal errors log the error's name only; listen errors log the error code only.
- A log that cannot be written is a silent no-op.

**Why:** Decision 0.8 and spec §9.2 say counts only, never a URL or the token. Withholding a whole line cannot leak a fragment, and a no-op cannot crash the daemon or reach stdio.

**Instead of:**
- an env-var override;
- keeping a partial first line;
- scrubbing the offending substring;
- logging error messages through `redact`.

**Revisit if:** Debugging the daemon in D6 needs more detail. Add codes or counts then, not text.

**By:** Claude (proposed)

- **F4 (NIT), open:** a daemon that loses the port race truncates the shared log before it tries to bind (`index.ts`, `log.ts`). In theory this can lose one line the winning daemon writes at that moment. It is not data loss in any practical sense; it could be fixed by truncating only after a successful `listen()`.
- **Measured fact, candidate gotcha:** a Node `setTimeout` delay above 2147483647 ms becomes 1 ms, with a `TimeoutOverflowWarning` on stderr. Any env-driven timer must be bounded.
