## 4. Handoff for S2b — the toggle API

- **The instance:** `safety` in `extension/src/sw.ts`, a `SafetyStore` (from `safety-state.ts`). S2b registers, at the top
  level of `sw.ts`: `chrome.action.onClicked.addListener(() => void safety.toggle().then(…badge…))`.
- **`safety.toggle(): Promise<"disarmed" | "armed" | "ignored">`** — the button and the shortcut (`_execute_action`).
  Armed → disarmed at once (never debounced). Disarmed → armed unless the last disarm (by the toggle *or* the options page,
  observed through `onChanged`) was under `REARM_GUARD_MS` = 1 000 ms ago → `"ignored"` (#144). Updates the memory copy and
  runs the disarm actions *before* writing `storage.local`. Serialised. An unreadable state toggles to disarmed. Writes only
  `safety.armed`.
- **Options page setter:** `writeSafety(set, change: Partial<StoredSafety>)` — `set` is `chrome.storage.local.set`; maps
  `{armed?, evaluate?, blockList?}` to the keys; not debounced. Options should read with `chrome.storage.local.get([...SAFETY_KEY_NAMES])`
  and `parseStoredSafety` (defaults for missing keys). The worker learns the change via `storage.onChanged` (already wired).
- **Badge at start-up (F42):** `await safety.read()` (or `safety.ingestView()` after `safety.ready`) gives `switches` and
  `blockedCount`; a rejection means unreadable → show `OFF` (fail closed).
- **Keys** (`SAFETY_KEYS`): `safety.armed` (boolean, default true), `safety.evaluate` (boolean, default true),
  `safety.blockList` (string, default ""). `sw-static.test.ts` already allows `options.ts` to import `safety-state.ts` and to
  call `storage.local.set`; the key strings must appear only in `safety-state.ts` (import `SAFETY_KEYS`).
- **Logging:** I added no toggle log line (0.7's "one line each" and the S2.3 scan are S2b's); `safety-state.ts` must stay
  free of `console.` (S1's static test).
- `debuggerSessions` (from `debugger.ts`) and `clearDownloads()` are run by `onDisarm`; nothing for S2b to add.

## 6. Deviations

- **Unknown method under the gated router**: `UNKNOWN_METHOD` in every state, no state read (decision 2 below).
- **The post-check also runs on an error reply** (not only a result): an error can carry page data (`LOCATOR_*` candidates).
  With armed, JS on, empty list it never fires.
- **The read ANDs the memory copy's disarm** (`read()` reports `armed:false` while the memory copy says disarmed although
  storage still says armed): stricter than F10's "the copy serves only the webRequest filter" (decision 4).
- **The capture verification's code is `OFFSCREEN`** (F11 said "refuse" without a code) — decision 5, contract-level.
- **`listTabs` with an unreadable state is refused** (`DISARMED`, unreadable message) rather than redacted.
- **`offscreen.ts` not hardened** — see Findings.

## 7. Proposed decisions

**2026-10-24 · S2a: the gated router sits beside the unchanged `Router` core**
Decided: `GatedRouter` in `router.ts` (own handler map; `on` calls `methodClass` and throws; `handle` gates before dispatch,
post-checks before the reply; gate throws → `INTERNAL`); `Router` unchanged; `sw.ts` constructs only `GatedRouter`
(static test). Why: `router.test.ts` registers unclassified names and must pass unchanged (the step agent's stage-local
design). Instead of: making `Router.on` throw (breaks existing tests); a subclass (shares a map that tests reach). Revisit
if: a second ungated construction is ever needed outside tests. By: Claude (step agent's design, built as briefed).

**2026-10-24 · S2a: an unknown method is `UNKNOWN_METHOD` in every state**
Decided: no state read, no handler, `UNKNOWN_METHOD` whether armed or disarmed. Why: no handler exists to gate; the answer
reveals nothing about the state and keeps the stale-extension diagnostic ("unknown method: locate" names a pre-Step-8
extension). Instead of: `DISARMED` while disarmed (would hide which build is loaded; needs a state read for a frame that
does nothing). Revisit if: the user wants disarmed to answer every frame alike. By: Claude.

**2026-10-24 · S2a: storage keys and the meaning of a wrong-typed value**
Decided: keys `safety.armed`, `safety.evaluate`, `safety.blockList` (namespaced, F36); a present key of the wrong type makes
the state unreadable → every call refused (`DISARMED`, unreadable message), the ingest drops everything, `toggle` writes
disarmed. Why: fail closed (#139). Instead of: treating a wrong type as its default (would re-arm on garbage). Revisit if: a
key needs migrating. By: Claude.

**2026-10-24 · S2a: a disarm held in memory wins over a storage read (contract-level)**
Decided: `SafetyStore.read()` reports `armed:false` when the memory copy is disarmed, even if `storage.local` still reads
armed (the toggle's write in flight, or a failed write). Why: between the click and the write landing, a call would
otherwise act after the human pressed OFF; it only ever refuses. Instead of: F10 literally (memory for webRequest only).
Revisit if: a failed write leaves memory and storage apart long enough to matter (memory reloads from storage at the next
worker start). By: Claude — contract-level (how the state is read), list under Open decisions.

**2026-10-24 · S2a: a capture whose window showed another tab is refused `OFFSCREEN` (contract-level)**
Decided: with the gated path, after `captureVisibleTab` the window's active tab is re-read; not the target → image
discarded, `OFFSCREEN` with `CAPTURE_MOVED_MESSAGE` (no URL/title). Why: F11 requires discard and refuse; `OFFSCREEN`
("not on screen") is the existing code that fits; no new code. Instead of: `INTERNAL`; returning the image (today, a leak of
another — possibly blocked — tab). Revisit if: S4 shows it firing in normal use. By: Claude — contract-level (a code chosen
for a refusal), list under Open decisions. Note: it can change a reply while armed with an empty list, but only in the race
where the window shows another tab at the capture (today that returns the wrong tab's pixels).

**2026-10-24 · S2a: the post-check also covers error replies; listTabs with an unreadable state is refused**
Decided: a handler's error is replaced by the post-check's refusal like a result; `listTabs` at receipt with an unreadable
state → `DISARMED` (unreadable). Why: errors can carry page data; fail closed. Instead of: post-checking results only;
redacting every row as `"disarmed"`. Revisit if: an agent needs a listing while the state is unreadable. By: Claude.

**2026-10-24 · S2a: the `seconds` wait is cut into 100 ms re-checked ticks**
Decided: F5's build choice taken; the text arm is checked before its page call and its reply is replaced by the post-check.
Why: a disarm ends a 60 s wait within one tick. Instead of: one sleep. Revisit if: the reads cost measurable CPU. By: Claude.

**2026-10-24 · S2a: tab events are redacted under a fresh state read, sent through one ordered chain**
Decided: each `tabCreated`/`tabRemoved`/`tabReplaced` frame waits for a `safety.read()` (failure → redacted as disarmed) and
goes out in order. Why: F10 keeps the memory copy for webRequest only; the chain keeps order. Instead of: the memory copy
(synchronous, no delay). Revisit if: S4 measures the delay breaking the opener rule. By: Claude.

**2026-10-24 · S2a: a closed tab's last URL is kept 610 s; the gate also uses the URL the call itself saw**
Decided: `TabInfoCache.retire` keeps the last URL for 610 s (≤ 1 000 tabs); a gone tab is tested by the cache's URL, else
the URL this call saw at an earlier phase; a replaced tab is followed (≤ 4 hops). Why: R2-1; the longest call is 600 s + 5 s.
Instead of: per-call pinning. Revisit if: #137's Revisit-if (a blocked page closing itself) is met. By: Claude.

**2026-10-24 · S2a: the network ingest drops a request for good once one event of it was dropped**
Decided: a dropped request id is remembered (≤ 5 000) so its later events are dropped too; a blocked event discards the
request's recorded hops; a disarmed drop does not discard (entries recorded while armed stay, F35); the pre-ready buffer
holds ≤ 2 000 events, oldest out (its request then dropped). Why: otherwise `entryFor` rebuilds the entry from a later
event (traffic of the disarmed period, or a blocked redirect). Instead of: per-event drop only. Revisit if: never. By: Claude.

**2026-10-24 · S2a: no state report when the state cannot be read**
Decided: `safetyState` is sent only from a successful read. Why: an unreadable state has no honest `blockedCount`; the
daemon keeps "not reported" (null). Instead of: reporting `{armed:false, evaluate:false, blockedCount:0}`. Revisit if: the
user prefers the disarmed report. By: Claude.

## 8. Findings

- **F-S2a-1 (outside the brief, in lane, not changed):** `offscreen.ts` acts on `{target:"offscreen", type:"send"|"connect"}`
  from **any** extension context; a content-script world able to call `chrome.runtime.sendMessage` could send frames to
  the daemon (e.g. a forged `safetyState`) or reconnect it. Our content script never messages; page script cannot reach the
  isolated world. Fix would be the mirror of `acceptRelaySender` (sender is the worker: no `tab`, `url` = the worker's
  script URL) — not built because that URL's exact value is unmeasured and a mistake silently breaks every reply; needs an
  S4 row first. Proposed for S2b or a later step.
- **Daemon ordering assumption (S3's lane, not changed):** the extension sends `safetyState` right after `ws-status` true,
  i.e. right behind its hello on the same socket; `wsHost.ts` handles the hello synchronously (`extensionConnected` resets
  the state to null, #165) before the next frame, so the report lands after the reset. If `extensionConnected` ever resets
  asynchronously, the report could be wiped — an S3-side check.
- F29 stands: after a disarm, `asRef`'s mark sweep is refused (it is a debugger session); the mark may stay on one element
  until reload. Not exempted (forbidden fix).
