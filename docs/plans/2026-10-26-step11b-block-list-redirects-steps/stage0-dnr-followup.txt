=== Part 1 — method and pass/record rules ===

Setup: installed branded Chrome (version read over the pipe, Browser.getVersion), a separate instance on a fresh
--user-data-dir %TEMP%\claude\s11b-stage0\followup\profile, --remote-debugging-pipe --enable-unsafe-extension-debugging
(CDP Extensions.loadUnpacked) and its own CDP port 18580; --host-resolver-rules
"MAP *.test 127.0.0.1, MAP *.example 127.0.0.1, MAP example 127.0.0.1, MAP *.123 127.0.0.1" (localhost resolves natively).
Same method as stage0-dnr-setup.txt (tools copied to the followup folder: launch.mjs loads four unpacked extensions,
run.mjs evaluates a script body in the probe's worker or a page). Extensions: "ext" = the Stage 0 probe
(stage0-dnr-ext-src.txt, unchanged); three twins with no background, each with the bridge's own permission list
(extension/manifest.json: debugger, tabs, scripting, activeTab, alarms, storage, offscreen, webRequest; host <all_urls>):
twin-nodnr (nothing added), twin-dnrha (+ declarativeNetRequestWithHostAccess), twin-dnr (+ declarativeNetRequest).
Servers, 127.0.0.1 only, ports checked free by netstat first (9234 never used): F = 18581 (tools/srv.py, any host
name, one log line per request with its Host header), W = 18584 (tools/ws.mjs, a WebSocket accept server: one line per
GET, per UPGRADE, per CLOSE). Every request carries a unique tag; a count is grep -c of the tag in the server's log.
R(E, tab) = session rule {priority 1, action block, condition {requestDomains:[E], tabIds:[tab], resourceTypes:["main_frame"]}}.

F-a (requestDomains acceptance and effect).
  Matcher side (no run needed, recorded from code): extension/src/safety-match.ts parsePatternLine (:118) via
  canonicalHost (:69-95): accepts my_host.example, localhost, example, xn--bcher-kva.example, a 63-char label and a
  64-char label (no label-length check: TYPED_NAME_RE :56, CANON_NAME_RE :58, the URL parser does not bound labels),
  1host.test; blocked.test. is accepted and canonicalised to blocked.test (dropTrailingDot :61, :82, :91); host.123
  is INVALID (new URL("http://host.123/") throws: a last label of digits is parsed as IPv4). Checked with tsx on
  parsePatternLine (2026-10-26).
  Accept (record): for each E in [my_host.example, localhost, example, xn--bcher-kva.example, <63 a>.example,
  <64 a>.example, host.123, blocked.test., blocked.test, 1host.test], one updateSessionRules({addRules:[R(E, work)]})
  alone; record accepted / rejected with Chrome's message; the set is cleared between entries.
  Effect: for each accepted E whose host is navigable, two legs on one background work tab, tabs.update + wait:
    control (no rule) http://<host>:18581/?tag=fa-<k>-ctl -> F 1 hit expected; 0 hits = NOT DISCRIMINATING for E.
    test (R(E, work) installed) tag fa-<k>-tst -> BLOCKS iff F 0 hits (and the worker's webRequest.onErrorOccurred
    records net::ERR_BLOCKED_BY_CLIENT); DOES NOT BLOCK iff F 1 hit.
  For blocked.test. the test leg is run twice: URL host blocked.test and URL host blocked.test. (trailing dot).

F-b (newTab via about:blank). Five iterations per variant, fixture URL http://allowed.test:18581/?tag=fb-...
  V1 (proposal 1): tabs.create({url:"about:blank", active:false}); R("blocked.test", id) installed;
     tabs.update(id, {url: allowed URL}); wait for complete.
  V2 (today's newTab, extension/src/handlers/tabs.ts): tabs.create({url: allowed URL, active:false}); wait.
  V3: as V1 but the update goes to http://blocked.test:18581/?tag=fb-... (blocked by the rule).
  Recorded per iteration: the probe's tabs.onCreated url and pendingUrl; after the load the tab's history via
  chrome.debugger Page.getNavigationHistory (entry count, currentIndex, entry URLs) and history.length via
  scripting.executeScript (V1, V2; V3's error page may refuse script: recorded as such); then chrome.tabs.goBack(id):
  resolves or rejects (message), and tab.url 1.5 s later.
  Reading: "the blank step adds a history entry" iff V1's entry count exceeds V2's in 5 of 5; "goBack returns to
  about:blank" iff V1's tab.url after goBack is about:blank in 5 of 5. Anything mixed is recorded as mixed.

F-c (can the extensions page prove the permission).
  Recorded from a chrome://extensions page target: chrome.developerPrivate.getExtensionsInfo() for the probe and the
  three twins (permissions.simplePermissions[].message and .submessages, permissions.runtimeHostPermissions, any
  warnings / installWarnings); chrome.management.getPermissionWarningsById(id) if available on that page; the
  details page chrome://extensions/?id=<twin> — the innerText of its permissions section (shadow DOM of
  extensions-detail-view).
  Reading: PROVABLE FROM THE PAGE iff twin-dnrha shows any permission line twin-nodnr does not; NOT PROVABLE iff the
  two are identical. Control: twin-dnr must differ from twin-nodnr (expected a "Block content on any page" line); if
  it does not, the page method is NOT DISCRIMINATING.

F-d (does a download-style rule hit the offscreen WebSocket). The probe opens an offscreen document (its
  offscreen.html); sockets are opened in that document by Runtime.evaluate: new WebSocket("ws://127.0.0.1:18584/?tag=..."),
  waiting up to 3 s for open / error / close.
  D-typed = {tabIds:[-1], initiatorDomains:[<probe id>], resourceTypes:["xmlhttprequest"], requestDomains:["127.0.0.1"]}
  D-untyped = the same without resourceTypes.
  d0 control, no rule, 3 sockets: OPEN expected (open event and W UPGRADE 1 each); otherwise NOT DISCRIMINATING.
  d1 D-typed, 3 sockets: PROTECTED iff 3 of 3 open and UPGRADE 1 each; HIT iff any fails with UPGRADE 0.
     Liveness of D-typed: under it, the worker's fetch("http://127.0.0.1:18584/?tag=fd-d1f-<i>") x3 -> 0 GETs and a
     rejection expected; if the fetch is not blocked, d1 is NOT DISCRIMINATING.
  d2 D-untyped, 3 sockets: HIT iff 3 of 3 fail (no open, UPGRADE 0); PROTECTED iff 3 of 3 open. Liveness: the same
     worker fetch x3 under D-untyped.
  d3 record: a socket opened with no rule, then D-untyped installed; 3 s later its readyState and whether W logged a
     CLOSE for it (does a new rule cut an established socket).
  d4 record: under D-typed and D-untyped, a fetch from the offscreen document to http://127.0.0.1:18584/?tag=...
     (whether the extension's other contexts match the download rule).
  Also recorded: the probe's webRequest events for each tag (type, tabId, initiator, error).

Teardown: Browser.close over the pipe (touch <followup>\stop); servers stopped by PID after checking their command line;
the profile folder checked for reparse points, then deleted; no chrome/node/python process whose command line names
the followup folder remains.
