## 5. Proposed decisions
### 2026-10-26 · A default-port pattern makes two regex rules
**Decided:** `host:80`/`:443`/`:21` become two anchored regex rules (no port on that port's schemes; the explicit port
on any scheme); `countRules` counts both. **Why:** one combined regex exceeds Chrome's 2048-byte regex memory cap
(verifier F1, RE2 at Chromium's Latin-1 settings), which would fail every covered call closed. **Instead of:** one regex
per pattern (#296 item 7), or case-sensitive matching (rewrites #296's wording). **Revisit if:** Run 17's
`isRegexSupported` record contradicts the estimate. **By:** Claude (proposed; step agent ruled).

### 2026-10-26 · Hosts past ~78–84 characters with a port or `*.` fail closed
**Decided:** no further shrinking; such a pattern's regex is rejected and the call refused (0.5); S3b's options caps
warning should name this case. Plain hosts (`requestDomains`) have no such limit. **Why:** measured boundary of the
smallest equivalent form. **Revisit if:** a human reports such a host. **By:** Claude (proposed).
