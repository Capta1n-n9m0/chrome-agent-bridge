## 5. Proposed decisions

### 2026-10-27 · S6: `newTab` lets its blank tab finish loading before it waits for the URL
**Decided:** the about:blank sequence waits for the blank tab's own `complete` (listener before `tabs.get`, 2 s bound,
never rejects) before arming the URL's load wait. **Why:** `waitForLoad` takes the first `complete` for the id (S6 V1).
**Instead of:** ignoring completes until a post-navigate `loading`; editing `waitForLoad` (outside the lane, shared).
**Revisit if:** Run 17b sees a `newTab` answer before the URL's load, a blank tab takes > 2 s to complete, or Chrome
reports the blank tab's `complete` twice (N1) — then add the post-navigate `loading` filter as well. **By:** Claude (proposed)

### 2026-10-27 · S6: a failed `tabs.update` closes the blank tab; a load timeout or a post-check refusal keeps the tab
**Decided:** as built; both verifiers agree the #311 STOP clause ("a blank tab after a refused install") is not hit by
the kept cases (the tab is not blank, the install was not refused). **Why:** keeps "no orphan tab" for a URL Chrome
refuses; otherwise behaviour as before S6. **Revisit if:** the user wants a refused `newTab` to close its tab, or
Chrome's `tabs.update` error text differs from `tabs.create`'s in a way a client relies on (S7 RECORD row, V5).
**By:** Claude (proposed)
