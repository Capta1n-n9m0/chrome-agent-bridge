## 4. Deviations — the blocker

The tab rules cannot be installed for a `newTab` from inside the lane (`tabs.ts`, `safety-call.ts`, a new pure module,
their tests):

- A call's DNR handle is made once, in the router factory in `sw.ts:75`:
  `new CallSafety(method, params, callDeps, dnrKeeper.call(method, params))`.
- `dnrKeeper.call` fixes the handle's scope at construction from `dnrScopeOf(method, params)`
  (`safety-dnr-keeper.ts:63-69, 131-134`): only class `navigate`, `back`, `forward` with an integer `tabId` get a tab
  scope. A `newTab` has no `tabId` when the call starts (the tab does not exist yet), so its handle is inert, and
  `Handle` has no way to take a tab id later (`scope` is a private readonly field, `:327`).
- The keeper instance lives only in `sw.ts`'s module scope; neither `tabs.ts` nor `safety-call.ts` can reach it.

So "install the tab rules through the existing keeper exactly as `navigate` does" needs one of these outside the lane.

## 5. Proposed decisions

### 2026-10-27 · S6: the new tab's handle comes from a `CallSafetyDeps` factory that `sw.ts` wires in one line
**Decided (proposed, for the session agent):** widen S6's lane by `extension/src/sw.ts`, one added line in `callDeps`:
`dnrForTab: (tabId) => dnrKeeper.call("navigate", { tabId })`. `CallSafetyDeps` (in lane) gains the optional
`dnrForTab`; `HandlerSafety` gains an optional `holdRulesFor(tabId)` that, on the blank tab, marks the epoch, re-runs
the gate's `effect` read, installs from that read's `BlockList` through a fresh tab-scoped handle, and fails closed
with the keeper's existing refusal; `post()` releases that handle in its `finally` beside the call's own, and reads
its `refusal()` after the release. `newTab` in `tabs.ts`: gate `effect()` on the URL as today → `tabs.create
{url:"about:blank"}` → `holdRulesFor(id)` (on throw: `tabs.remove(id)`, rethrow, no navigation) → `tabs.update(id,
{url})` → `waitForLoad` as today → `{id}`. No URL or `about:blank`: today's path, unchanged. The keeper itself is not
edited: the handle is a `navigate`-class tab handle, so its caps, epoch, rebuild and release rules are the ones
`navigate` already passes.
**Why:** the smallest change that uses the keeper unchanged; the `sw.ts` line adds no listener, log or top-level
`await`. Without `sw.ts` wiring the in-lane code would be dead and Run 17b's R17B-RD-2 would leak as before.
**Instead of:** (B) widening the lane to `safety-dnr-keeper.ts` (a `callForTab(tabId)` method or a late-bound scope:
touches the keeper and its tests, which S2's verifier signed off); (C) passing the keeper itself into `CallSafety`
(widens the surface the handler can reach).
**Revisit if:** the session agent prefers (B), or `sw.ts` is held to a no-edit rule this report does not know of.
