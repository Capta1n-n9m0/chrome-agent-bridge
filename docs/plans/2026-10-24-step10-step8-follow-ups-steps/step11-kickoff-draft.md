# Step 11 kickoff draft — design proposals in brief (2026-10-25, docs builder; not committed)

Files: `docs/plans/2026-10-25-step11-file-upload.md` (phase doc), `docs/plans/next-session-prompt.md` (kickoff). #229 is folded in: the precondition is met, and stage S1 covers #227 (b) and `kind` in the `saveTo` description. Run 16 adds SAVE-REFUSE-R and SW-2 (a warm-up trial, then 0.8's outcome table; S5b only if the wait runs to its bound). The #140 network rule is its own step after Step 11.
1. **Paths, not bytes (0.3):** the client sends absolute paths and Chrome reads them through `DOM.setFileInputFiles`. Rejected: bytes in chunks plus a `DataTransfer` in the page. Because of this the extension sees the path, so "never log a path" applies to every layer.
2. **Upload folders (0.4, security):** a list the human keeps in `storage.local` (`safety.uploadFolders`). It is empty by default, so uploads are off until the human adds a folder. It is edited only on the options page and enforced in the extension. The matcher (`upload-paths.ts`) checks for a separator boundary, ignores case for drive-letter paths but not POSIX paths, and refuses `..`, UNC paths, `\\?\`, alternate data streams and relative paths. The SDK and the MCP send `fs.realpath`, so a junction that points outside an allowed folder is refused. Rejected options: no rule, an allow-list in the SDK or its environment. Per-upload confirmation is left for later.
3. **Gate (0.5):** a new safety class `upload`: the tab's tests come first (`DISARMED`, then `DOMAIN_BLOCKED`), then the folder rule. A failure there gets a new code `UPLOAD_REFUSED` (27 codes, 26 on the wire) with a fixed message that names no path or folder. The code is not in the attach set, and the JavaScript switch does not apply.
4. **Wire (0.6):** a tab method `uploadFiles {tab, ref|locator, paths[1–20]}` → `{files}`, in `TAB_METHODS`. It takes no lock and no `focusFirst`, because this is not `Input.*`. Run 16's UP-1 measures it on a background tab, with the outcome table written before the run.
5. **Element (0.7):** the target is a file input, a `<label>` whose control is one, or an element with exactly one file input inside it. This reaches hidden inputs without touching `a11y.ts`. To get from the content script to CDP, a one-off attribute mark is set, a closure-free finder returns an `objectId`, and the mark is removed on every path.
6. **SDK (0.8):** `tab.upload(target, paths, {timeoutMs?})` → `{files:[{name, bytes, sha256}]}`, plus the `client.upload` mirror. A preflight (absolute, exists, a regular file, the real path) makes no call when it refuses. The new types are `UploadOptions` and `UploadResult`; the SDK still exports exactly eight values.
7. **MCP (0.9):** `browser_upload_file {ref?, locator?, paths, tab?}` is tool 24. Its answer gives basenames, sizes and sha256s only. It warns never to click a file input. The schema baseline is re-baselined by one recorded entry, after S1's `browser_evaluate` re-baseline.
8. **Run 16 (0.12):** the fixture hashes each received `File` in the page. Rows: UP-0…UP-9 (background, multiple, hidden-via-label, shadow root and frame, the MCP leg, refusals that leave 0 files, safety states, CSP, a junction), UP-LOGS, and UP-CLICK as RECORD only. The restore includes the Upload folders hash.
9. **Stages:** Stage 0 (2 h) → S1 (1 h) → S2 contract (2.5 h) → S3 extension ∥ S4 SDK and MCP (3 h / 2 h) → S5 Run 16 (1.5 h + 1.5 h, alone) → S6 docs (1 h). Gates: G11-1 any push, and G11-2 any non-fixture upload. Editing the options page's Upload folders inside the wave is proposed as covered by #33, with an exact restore.
10. **Kickoff:** every agent runs Opus 5.5 (headless actors with `--model opus`). Commits carry only the `Co-Authored-By: Claude Opus 5.5` trailer.
