## Proposed decisions

### 2026-10-25 · S3: a match inside the 800th listable element counts as past the cap (on pages with more than 800)
**Decided:** keep 0.3's letter — a non-listable match that comes after the 800th listable element in walk order is past
the cap, including a descendant of the 800th itself (pre-order), when the page has > 800 listable elements; pinned by a
test. **Why:** 0.3 is a (user) decision; reinterpreting "after in walk order" is not the step agent's to do. **Instead
of:** treating a match inside a listed listable ancestor as not past (then the MCP line would not say "browser_snapshot
does not list it" while the snapshot shows the enclosing button). **Revisit if:** the user prefers the ancestor rule.
**By:** Claude (touches a (user) decision's wording — open for the user)

### 2026-10-25 · S3: the SDK's `warning` fires before the action resolves; a throwing listener is ignored; `locate()` emits none
**Decided:** as built. **Why:** a script awaiting `tab.click()` has seen the warning by its next line; a listener bug
must not turn a successful action into an error; `locate()` already returns the flag. **Instead of:** a later tick; a
rejecting listener; an event for `locate()`/`call()` too. **Revisit if:** a strict mode (warnings as errors) is wanted.
**By:** Claude

### 2026-10-25 · S3: a type-only export `BridgeWarning`
**Decided:** `@bridge/sdk` exports the type `BridgeWarning` (no new value; the eight values unchanged). **Why:** users
would otherwise restate the payload's shape. **Instead of:** no exported name. **Revisit if:** the user rules #206
otherwise. **By:** Claude (SDK surface — carry under #206's open decision)

### 2026-10-25 · S3: the MCP warning line's wording and placement
**Decided:** 0.3's text verbatim as `CAP_WARNING_LINE`, the last line of a successful answer (after a cursor notice);
never on a failure report. **By:** Claude (build decision)
