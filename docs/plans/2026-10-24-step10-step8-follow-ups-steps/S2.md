## Proposed decisions

1. **2026-10-25 · The tool-schema baseline is captured through a real `tools/list`.** *Decided:* names + `inputSchema`
   through the MCP SDK client ↔ in-memory transport ↔ server, keys sorted, tool descriptions excluded, parameter
   descriptions included. *Why:* byte-for-byte what Claude Code receives, the SDK's own zod → JSON Schema conversion
   included. *Instead of:* `_registeredTools[…].inputSchema` zod objects, or our own `zod-to-json-schema` call.
   *Revisit if:* an MCP SDK upgrade changes the emitted JSON Schema with no tool change — a dated, user-ruled
   re-baseline, never a silent regeneration. By: Claude.
2. **2026-10-25 · A failed focus answers as `browser_focus_tab` would.** *Decided:* the trusted action's answer on a
   `focusTab` error is `browser_focus_tab`'s for that error (one line for `DISARMED`/`DOMAIN_BLOCKED`; an attach-set
   code such as `TIMEOUT`/`OFFSCREEN` gives a failure report with a screenshot). *Why:* 0.2 says the focus failure is
   the answer; one path, no new rendering. *Instead of:* a prefix such as "Focus before the trusted click failed:".
   *Revisit if:* MCPF-1 or a user finds the report misleading (verifier MINOR 2: it reads like the click's own failure
   though the click was never sent). By: Claude.
3. **2026-10-25 · The description wording.** *Decided:* the sentence above on the three tools, and
   `browser_focus_tab` no longer claims to be "the only tool that changes what the human sees". *Why:* 0.2 asks the
   three descriptions to say it; the old claim became false. *Instead of:* leaving `browser_focus_tab`'s text
   (false) or a longer explanation of F19 in every description. *Revisit if:* an MCP actor in S7 misreads the sentence (e.g. calls `browser_focus_tab` before every trusted
   call). By: Claude.
