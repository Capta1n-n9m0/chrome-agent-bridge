## Proposed decisions

- **2026-10-22 · "No tab with id" from the extension is `TAB_UNKNOWN`; the daemon owns any mapping to `TAB_GONE`.**
  - Decided: the extension follows phase-doc 0.1, not Stage 0 F21's proposal, which was never
    recorded.
  - Why: 0.1 is the design of record. The daemon knows whether a handle existed and can answer
    `TAB_GONE` itself.
  - Instead of: `TAB_GONE` from the extension.
  - Revisit if: T2 forwards the extension's code unchanged for a valid handle.
- **2026-10-22 · The no-normal-window message is defined in `errors.ts`; T3.3 is sharpened to grep `focused\s*:`.**
  - Decided: the F8 text (which contains "focused") lives in `errors.ts`, and T3.3 adds
    `grep -nE "focused\s*:" extension/src/tabs.ts extension/src/errors.ts` → nothing.
  - Why: T3.3's intent is no focus key and no focus change, not no message word. The verifier ruled
    the move acceptable only with the grep sharpened (NIT 3).
  - Instead of: the string in `tabs.ts`, which fails T3.3 on a message.
  - Revisit if: T3 needs a focus call in `tabs.ts`.
- **2026-10-22 · `listTabs` marks the human's tab with `current: true`, omitted elsewhere; `active` keeps its per-window meaning.**
  - Why: F8 and #43. It is additive, so today's readers are unchanged. It is what T2's
    `tabs.claim {active:true}` and T4's status should read.
  - Instead of: redefining `active`.
  - Revisit if: T4 prefers a `current: false` on every tab.
- **2026-10-22 · An unknown method gets `UNKNOWN_METHOD` from the extension.**
  - Why: it is honest and the message is unchanged. Stale-extension checks match the text (F22).
  - Instead of: `INTERNAL`.
  - Revisit if: a client must tell the daemon's `UNKNOWN_METHOD` from the extension's.
- **2026-10-22 · A viewport screenshot of an explicit background `tabId` is refused until T3.**
  - Why: `captureVisibleTab` would silently return another tab's pixels.
  - Instead of: capturing the visible tab.
  - Revisit if: T3 lands `activateForCapture`, which removes it.
- **2026-10-22 · `PAGE_ERROR.data` is `{name: className ?? "Error", stack?}`.** `stack` is the
  formatted description, at most 8 lines and 2000 characters, present only when it has more than one
  line.
  - Why: keeps `data` bounded.
  - Instead of: the raw uncapped description.
  - Revisit if: the SDK's failure enrichment wants the full stack.
- **2026-10-22 · `describeDebuggerError` recognises our errors by `name === "BridgeError"` plus a string `code`.**
  - Why: keeps the pure module import-free.
  - Instead of: importing the class.
- **2026-10-22 · NET-1's expected size follows the fixture (12.8 KB) — for the session agent / T5.** See Deviation 6.
