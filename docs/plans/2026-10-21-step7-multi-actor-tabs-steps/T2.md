## Outputs

- New pure modules in `daemon/src/`:
  - `handles.ts`: `HandleTable`. Its `mint` is idempotent, and handles `T<n>` are monotonic.
    - `resolve` returns live, gone or unknown.
    - `replace`, `remove` (keeps `lastUrl`/`lastTitle`) and `prune` (1 h / 1 000) manage entries.
    - `lastHandleOf` gives the newest dead handle; there is also a url/title cache.
  - `leases.ts`: `LeaseTable`, keyed by handle.
  - `lock.ts`: `VisibilityLock`.
    - Waiters are served FIFO, and each release is per-acquisition and idempotent.
    - At the deadline a waiter gets `LOCK_TIMEOUT {holder}`.
    - `releaseAllOf(clientId)` frees a disconnected client's hold and waits; clock and timers are injected.
  - `methods.ts`: the one method table (#39), with `classify` and `takesLock`.
- New `daemon/src/intercept.ts`, the tab layer. It handles:
  - resolution (handle, legacy human's tab via `listTabs` `current:true`, legacy Chrome id);
  - the lease check, plus a re-check after the lock wait;
  - the lock, with one deadline (#44);
  - forwarding with numeric `tabId` and no `tab`;
  - the `listTabs`/`newTab`/`closeTab` intercepts and `tabs.claim`/`tabs.release`;
  - network scopes (#40 as amended by #54; `{scope:"all"}` per #52) and the F12 entry `tab`;
  - the `networkClear {tab:"all"}` foreign-entries refusal, which fails closed;
  - extension events, validated by T0's guards: `leaseGranted` and `tabGone`;
  - F15 resync on a proto:2 hello, F20 (opener grant at once, event held back while a `newTab` is in flight), and the #42 `VERSION` gate.
- Changed files in `daemon/src/`:
  - `bridge.ts` adds `notConnectedError()`, which keeps the Step 6 text.
  - `registry.ts` adds `nameOf`.
  - `route.ts`:
    - `RouteContext` gains optional `tabs` and `caller`;
    - `daemon.status` adds `tabs` and `lock` when the layer is present.
  - `wsHost.ts`:
    - every client context carries the layer and `caller`;
    - the extension's `proto` is read beside `parseHello`;
    - events are counted and applied;
    - `clientGone` runs on close;

## Proposed decisions

All 2026-10-22, By: Claude. Format: Decided / Why / Instead of / Revisit if.

1. **`tabReplaced` onto a tab that already has a handle.**
   - Decided: the removed tab's handle wins, unless it is unleased and the added tab's handle is leased. The loser is marked gone, and its holder gets `tabGone`.
   - Why: never retire a leased handle when an unleased one can go.
   - Instead of: always retiring the added tab's handle.
   - Revisit if: LEASE-6 shows this case.
2. **`closeTab`/`selectTab`/`focusTab` with neither `tab` nor `id`.**
   - Decided: `BAD_PARAMS "tab is required"`.
   - Why: F4, no destructive default on the human's tab.
   - Instead of: the legacy human's-tab path.
   - Revisit if: Step 8 S2.
3. **A no-proto extension gets `listTabs`/`newTab` and the free methods forwarded exactly as in Step 6.**
   - Decided: no handles are minted and no lease is granted.
   - Why: #42 refuses tab methods, so handles would be unusable.
   - Instead of: annotating its results.
   - Revisit if: a status view needs handles while the extension is stale.
4. **The lease is re-checked, and the handle re-resolved, after the lock is acquired.**
   - Decided: on failure the lock is released and the error returned.
   - Why: stricter; a claim made during the wait is honoured.
   - Instead of: checking before the wait only.
   - Revisit if: latency shows it.
5. **No `tabGone` goes to the client that closed the tab itself.**
   - Decided: a `closing` map suppresses it only when the holder is the closer.
   - Why: that client already has its answer.
   - Instead of: always sending it.
   - Revisit if: an SDK wants it.
6. **Network scope details.**
   - Decided:
     - an explicit `"active"` resolves to the human's tab without the legacy log line;
     - `networkRequests {id}` drops the scope;
     - anything that is neither a string nor an integer → `BAD_PARAMS`;
     - any other string is read as a handle (`TAB_UNKNOWN` when bad).
   - Why: `"active"` is a valid Step 7 scope, not a legacy form.
   - Instead of: logging every resolution.
   - Revisit if: Step 8 redesigns the network tools.
7. **F12 entry `tab`.**
   - Decided: the live handle or the newest dead one (`lastHandleOf`); an unseen or negative `tabId` gets no `tab`.
   - Why: no live handles for tabs that may not exist (V3).
   - Instead of: minting.
   - Revisit if: the MCP needs every entry to carry a handle.
8. **Error texts.**
   - `TAB_GONE`: `tab T3 was closed — call listTabs to pick another tab`, data `{tab, lastUrl?, lastTitle?}` (the URL stays out of the message).
   - `TAB_UNKNOWN`: `unknown tab handle T9 — call listTabs` / `unknown tab id N — call listTabs`.
   - `TAB_HELD`: Stage 0's proposed text, with the time as UTC `HH:MM:SS`, data `{owner, since}`.
   - `LOCK_TIMEOUT`: `timed out waiting for the visibility lock, held by "A"`.
   - Why: actionable, and no URL in any message text.
   - Revisit if: T4's rendering wants another shape.
9. **Results.**
   - Decided: `tabs.claim` returns `{tab}` only (spec §6.2); `tabs.release` returns `{ok:true}`; `newTab`/`listTabs` keep the Chrome `id` beside `tab` for the one release.
   - Why: Step 6 clients read `id`.
   - Revisit if: Step 8 S2.
10. **A replaced extension socket.**
    - Decided: its events are counted and ignored, and a late resync from it is dropped.
    - Why: only the current extension is truth.
11. **A client that disconnected during its `newTab` or `tabs.claim {active}`.**
    - Decided: it is granted nothing, and a lock call from a gone caller is refused before acquiring.
    - Why: no leaked leases or lock.
12. **A deadline already passed before a sub-call.**
    - Decided: `TIMEOUT "Timed out before calling <method>"`, not forwarded.
    - Why: #44, one deadline.
13. **F20 while a `newTab` is in flight.**
    - Decided: the opener grant takes effect at once; only the `leaseGranted` event is held back, until the in-flight `newTab` calls settle, and it is dropped if `newTab` took the tab.
    - Why: no unheld window, and no wrong event.
    - Instead of: deferring the whole decision.
    - Revisit if: T5 LEASE-3 shows a delayed event that matters.
14. **`networkClear {tab:"all"}` fails closed.**
    - Decided: a foreign-held tab whose probe throws or returns a non-numeric `total` counts as having entries → `TAB_HELD`.
    - Why: never loosen on doubt (V8).
    - Instead of: failing open.

## Findings

- **V5, ruled by the session agent:**
  - The code is right: `networkRequests` is free in every scope, including a legacy number (spec §6.3), and `networkClear` with a number is lease-checked.
  - #54's "lease-checked" gets a dated note from the session agent.
- **V4, a design-level follow-up proposal.**
  - The problem: the F15 resync on an extension reconnect cannot tell that Chrome restarted and reused a tab id. A held handle could then point at a different tab.
  - The proposal: a session marker in the extension's hello (e.g. a random id per service-worker or Chrome session). On a changed marker the daemon retires every handle, sending `tabGone`.
  - This is a wire change, so it is not in T2.
- **NITs:**
  - V6: `route.ts` falls back to Step 6 forwarding when `caller` is missing; `WsHost` never does that.
  - V7: the legacy log line also fires for a Step 7 network call with no `tab`. It still fires once per client.
  - V9: if a `newTab` caller disconnects, the opener's holder may get `leaseGranted` for that tab. That is a misattribution, not a loosening.
- **Known gaps:**
  - The race between the check and the clear in `networkClear {tab:"all"}` (several awaits) remains. A foreign tab that gains entries between the probe and the clear is cleared.
  - `newTab` does not cache its requested URL, so `daemon.status` shows no `url` for it until the next `listTabs`.
  - Two tests are slow by design (one-deadline about 5 s, ATK-L5 about 7 s).
- **Logging:** no URL, title or token in any new log line. No new `console.*` lines.
