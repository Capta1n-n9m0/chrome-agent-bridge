## Verifier verdict

The full findings are in `T3-verifier.md`.

**Round 0: FAIL.**
- **V1, MAJOR:** the extension checked `fullPage === true`, but the daemon's `takesLock` skips the lock
  on any truthy `fullPage`. So `fullPage: 1` switched tabs with no lock held.
- **Fixed in round 1:**
  - V1: the extension now uses the daemon's truthy rule, with a test.
  - V2: a hung Chrome call wedged the window's chain forever. It is now bounded at 30 s, with a test.
  - V3: the two disclosed deviations now have tests.
  - V8: a test now pins that `networkRequests` returns no `text`.
  - V9: one test waited 0.5 s of real time; it no longer does.

**Round 1: PASS-with-notes.** Open notes:
- **V4, MINOR:** `focusTab` is outside the extension's per-window chain. After the daemon gives up on
  a capture, that capture's restore can undo a later `focusTab`.
- **V5, NIT:** a tab dragged to another window while queued is captured from the old window id.
- **V6, NIT:** the 500 ms spacing holds between reserved slots, not between the actual captures. The
  quota retry absorbs the gap.
- **V7, NIT:** the builder counted 5 `count` assertions; there are 6, all converted.
- **V10, NIT:** the alias's `BAD_PARAMS` text now says `focusTab requires tabId`.
- **R1-1, NIT:** `fullPage: "false"` (a truthy string) takes the CDP path. That is consistent with the
  daemon's lock rule; the MCP sends booleans only.

## Deviations

- **The `selectTab` alias's `BAD_PARAMS` message names `focusTab`.** An alias cannot know which name
  it was called by. The existing test checks only the code, so no expected text was edited.
- **`fullPage` is read as truthy rather than `=== true`** (V1). The extension must switch tabs only
  where the daemon locks. The alternative, tightening both sides to `=== true`, is outside T3's lane.
- **A target tab closed mid-switch gives `TAB_UNKNOWN`** (through `asTabUnknown`). A window with no
  active tab captures with no restore. Both are tested.
- **The plan's "restore, not awaited for the result" holds for the caller.** The per-window chain
  does wait for the restore, so F19 holds.

## Proposed decisions

### 2026-10-22 · T3's snapshot element fields (T3)
**Decided:**
- `depth` is the number of *listed* ancestors (across open shadow roots and frames).
- `frame` is the 1-based order in which the walk enters same-origin frames, absent for the top document.
- `disabled` appears only as `true`.
- `checked` applies to checkbox, radio, switch, menuitemcheckbox and menuitemradio.
- `expanded` comes from `aria-expanded`, or from `<details open>` for a `<summary>`.
- `selected` comes from an `<option>` or from `aria-selected`.
- `href` is the resolved `a[href]`.
- `value` applies to text inputs and textareas, spinbutton, slider and `<select>`. It is capped at
  120 characters. It is never sent for a password input, and an empty value is sent as `""`.
- Element kinds are tested by tag name, not `instanceof`, because frame elements belong to another realm.

**Why:** 0.7 names the fields but not their meaning. Listed-ancestor depth is what an indented tree
needs. A password must not go on the wire.

**Instead of:**
- DOM depth;
- a 0-based frame index;
- omitting an empty value;
- `instanceof`, which drops every framed element's fields (measured in jsdom).

**Revisit if:** T4's formatter or Step 8 locators need another depth, or the user wants no form
values on the wire at all.

**By:** Claude

### 2026-10-22 · `activateForCapture`'s order, spacing and per-window chain (T3)
**Decided:**
- The minimized check comes first.
- The 500 ms global capture slot is reserved before the switch (F10), so the switched tab is on
  screen for as short a time as possible.
- A quota error gets one retry after 500 ms.
- A per-window chain (F19) is released when the restore settles, or at most 30 s after the link
  started (the daemon's default call timeout; spec §6.4 "a hung screenshot cannot wedge everyone").
- The extension switches tabs exactly where the daemon locks: `fullPage` is read as truthy, as
  `takesLock` reads it.

**Why:** Stage 0 F10 and F19, and verifier V1 and V2.

**Instead of:**
- spacing measured between actual captures, which keeps the tab on screen longer;
- an unbounded chain, where a hung call wedges the window for the worker's lifetime;
- a 2 s bound, which could cut a slow but legitimate switch;
- `fullPage === true`, which lets a truthy non-boolean switch with no lock.

**Revisit if:** T5 SCREEN-3 sees a quota error the retry cannot absorb, or V4's `focusTab` race
shows up live.

**By:** Claude

### 2026-10-22 · `selectTab` is the same function as `focusTab` (T3)
**Decided:** `export const selectTab = focusTab`, and `sw.ts` registers both names to `focusTab`.
Its `BAD_PARAMS` text names `focusTab`.

**Why:** T3.5 requires the same handler.

**Instead of:** a wrapper that keeps the old method name in the message.

**Revisit if:** Step 8 S2 removes the alias.

**By:** Claude

## Findings

1. **Pre-existing: nested same-origin frames are never entered.**
   - `frameDocument` uses `instanceof HTMLIFrameElement`, and the listbox rule uses
     `instanceof HTMLSelectElement`. Both fail for framed elements, which belong to another realm.
   - The result: a frame inside a frame is skipped, and a `<select size>` inside a frame lists as a
     combobox.
   - Left unchanged, because T4.2's baseline must be reproducible from `51de800`'s walk. This is a
     candidate for after T4.

   - `browser_snapshot` prints `undefined`, because `mcp/src/tools/registry.ts:82-83` reads `text`;
   - `browser_network_requests` prints an empty string;
   - `browser_new_tab` opens a background tab, because it passes no `active`.

   All three are T4's to fix, and none is visible before T5's reload.
3. **V4:** see Verifier verdict. A candidate fix is to run `focusTab` through the same per-window
   chain. That is a design-local decision for after T5.
