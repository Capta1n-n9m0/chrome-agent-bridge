## 5. Proposed decisions

### 2026-10-23 · With no cursor yet, browser_new_tab opens in the background
**Decided:** `browser_new_tab` sends `active: true` only when the cursor is set and `listTabs` shows its
tab as `current`. Three cases open in the background, and the result then adds ` (in the background —
browser_focus_tab shows it)`:
- no cursor, which is a session's first tab (Stage 0 F26);
- a lost cursor;
- a failed `listTabs`.

The tool always moves the cursor to the new tab and never sends `focusTab`.
**Why:** phase doc 0.6's rule is pre-stated and applied literally. On doubt, the human's view does not
change.
**Instead of:** treating no cursor as "the human is watching" and opening in front, as Step 7 did. That
is friendlier for "open X in a new tab", but it is a change to 0.6, so it is the user's call.
**Revisit if:** E2E (CUR-3 (c), TAB-3) shows a model losing track of a tab it opened in the background,
or the user wants a session's first tab in front.
**By:** Claude (pre-stated rule; F26 was unruled; contract-level, what the human sees: for user review)

### 2026-10-23 · browser_status keeps `Active tab:` and adds `Cursor:` and `Human's active tab:`
**Decided:** the Step 7 lines stay byte-identical. With the extension connected, a line follows in one
of these forms:
- `Cursor: T3 "Title" — url (held by me | held by <owner> | not held)`;
- `Cursor: T3 (not open any more)`;
- `Cursor: none yet — the first tab tool claims the human's active tab`.

A `Human's active tab: T7 "…" — not mine; call browser_use_active_tab to work there` line comes only when
a cursor exists and the human's tab differs from it. When another actor holds the human's tab, that line
reads `— held by <owner>, not mine`. `browser_status` never claims, and its not-connected branches are
unchanged and make no call.
**Why:** STAT-1, MUX-1 and MUX-8 quote `Active tab:`, and lines added after it keep recorded runs
readable. Suggesting a claim that `TAB_HELD` would refuse misleads the model.
**Instead of:** replacing `Active tab:` with 0.6's pair; showing the suggestion even when another actor
holds the tab.
**Revisit if:** E2E shows models confused by `Active tab:` and `Human's active tab:` naming the same tab.
After a lost cursor, the line reads `Cursor: none yet` (verifier NIT 3). Wording only: the next tool's
notice explains the loss.
**By:** Claude (MCP tool output: for user review)

### 2026-10-23 · browser_press_key stays untargeted
**Decided:** `browser_press_key` gets no `ref` and no `locator`, and presses on the focused element as
before.
**Why:** #92 item 2 keeps the SDK's `pressKey` untargeted this step, and the MCP mirrors it. #83 adds a
target to actions that already took a `ref`, and `browser_press_key` never took one.
**Instead of:** a locator that focuses an element first. The extension supports it, but the tool schema
would grow beyond #83.
**Revisit if:** E2E shows models needing a click-then-press pair often, or 0.4 gains a `pressKey` target.
**By:** Claude (tool schema: for user review)

### 2026-10-23 · browser_wait_for takes `locator` and `state`, not `timeoutMs`
**Decided:** `browser_wait_for` gains `locator`, with the same nested schema as the actions, and
`state: "visible" | "hidden"`, which is allowed only with a locator. A locator together with `text`,
`seconds`, `networkIdle` or `idleMs` is a tool error and nothing is called. The locator wait uses the
extension's default bound of 10 s, and the tool has no `timeoutMs` field.
**Why:** 0.2 defines `waitFor {locator, state?, timeoutMs}`, and `hidden` cannot be expressed without
`state`. A fixed 10 s matches the tool's other wait kinds ("up to 10s").
**Instead of:** exposing the wire's `timeoutMs`; ignoring the stray fields.
**Revisit if:** real pages need locator waits longer than 10 s (S6).
**By:** Claude (tool schema: for user review)

### 2026-10-23 · The MCP renders failure reports in its tab wrapper through `@bridge/sdk/report`
**Decided:** the MCP's tab wrapper (`onTab`) passes an error to `attachContext` (#93 item 2) only when
all three hold:
- it is a `BridgeError`;
- its code is in the attach set (`LOCATOR_NOT_FOUND LOCATOR_AMBIGUOUS REF_STALE OFFSCREEN PAGE_ERROR
  NAV_FAILED TIMEOUT`);
- its target is a `T<n>` handle (never `"all"`).

`attachContext` gets the MCP's raw call. The tool then returns `isError` with `report()` as the text, a
`Full message:` block when the message is multi-line or over 300 characters, and the saved PNG as an
image block when it can be read. Every other error is rethrown unchanged, so today's texts stay.

Validation errors, `browser_status`, `browser_list_tabs`, `browser_select_tab`/`browser_close_tab`/
`browser_new_tab`, `browser_use_active_tab`, `browser_download` and the network id lookup never attach.
`registerTools` options make the clock, timers, env, home directory and `attach` injectable, and
production uses the defaults.

A `browser_evaluate` page exception (`PAGE_ERROR`) is therefore reported in full: a snapshot that
renumbers the tab's refs, a default-mode screenshot (~1.5 s flash on a background tab) and a PNG under
`~/.chrome-agent-bridge/failures/`.
**Why:** S5's checkbox, 0.5 and #93 applied literally. Wrapping `BridgeLink.call` instead would also
enrich the cursor claim, the status listing and the report's own reads.
**Instead of:** skipping `PAGE_ERROR` (or its screenshot) for `browser_evaluate`, a change to the attach
set and therefore contract-level; rendering `data.stack` in `report()`, which is an SDK change outside
S5's lane.
**Revisit if:** exploratory `browser_evaluate` errors make the flash or the ref renumbering a nuisance in
E2E (REP-1, S6). The likely fix would be to drop `PAGE_ERROR` from the MCP's attach set.
**By:** Claude (the attach set as it applies to the MCP: for user review)

### 2026-10-23 · Wait calls carry their own bound
**Decided:** the call `timeoutMs` of `browser_wait_for` depends on the wait kind:
- 15 000 ms for `locator`, `text`, `networkIdle` and an empty call;
- `seconds × 1000 + 5000` ms for a `seconds` wait.

`browser_evaluate` keeps its page timeout + 5 s.
**Why:** #90 item 5 and F22. A 60 s `seconds` wait used to hit the 30 s default call timeout.
**Instead of:** the 30 s default for every kind.
**Revisit if:** the extension's 10 s wait bound changes.
**By:** Claude

## For the as-built register

### Contracts (binding forward)
- **Tools:** 23 by `grep -c "server.tool("`. The new tool is `browser_use_active_tab {}`, which sends
  `tabs.claim {active:true}` and sets the cursor.
- **Cursor:** it moves only on first touch, `browser_select_tab`, `browser_new_tab` and
  `browser_use_active_tab`. An explicit `tab` never moves it, and neither does `browser_status`.
- **`browser_new_tab`:** `active` is true only when cursor = the `current` row of `listTabs`, and false
  otherwise (no cursor, lost cursor, listing failure). The result then ends ` (in the background —
  browser_focus_tab shows it)`.
- **`browser_status`:** the Step 7 lines stay byte-identical, then a `Cursor:` line, then
  `Human's active tab:` only when it differs. It never claims.
- **Actions:** click, type, hover and select_option take exactly one of `ref` and
  `locator {role?, name?: string, exact?, text?, css?, nth?: int ≥ 0}`. Scroll takes either or neither.
  Both are checked before any call, the claim included. The wire gets `{locator}` without a `ref` key,
  or the reverse. `browser_press_key` is unchanged.
- **`browser_wait_for`:** `locator` + `state` stand alone (a locator with `text`, `seconds`,
  `networkIdle` or `idleMs` is a tool error). The call timeout is 15 000 ms, or `s·1000+5000` for
  `seconds`.
- **`browser_evaluate`:** `asRef` is forwarded only when true, and a returned ref prints
  `[ref=eN] — pass it as ref to browser_click etc.`.
- **Failure reports:** attach-set code + `T<n>` handle → `attachContext` from `@bridge/sdk/report` →
  `isError` with `report()` [+ `Full message:`] + a PNG image block. Every other error is rethrown
  unchanged.
- **SDK:** `sdk/package.json` `exports["./report"]` points at `sdk/src/report.ts`, which only
  re-exports. The main entry keeps its 8 values.
- **`registerTools`:** the signature is `(server, bridge, cursor?, options?: {actorName?,
  failureReports?, attach?})`.
