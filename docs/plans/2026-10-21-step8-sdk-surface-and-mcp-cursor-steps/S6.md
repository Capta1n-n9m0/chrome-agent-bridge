### 2026-10-23 · SM-1's log clause cannot hold for a tab that `chrome://quit` closes (proposed)
**Decided (proposed):** SM-1's rule "the session change retires `<n> ≥ 1` handles" is wrong for its own set-up:
`chrome://quit` closes the held tab first (`tabGone` at the quit), so the restart's `extension session changed`
retires 0. The safety property SM-1 exists for held (no handle survived the restart; daemon pid unchanged; counts
equal). A re-run needs a new pre-registered clause, e.g. "the held handle is gone after the restart (by `tabGone`
at the quit or by the session change), a call on it gives `TAB_GONE`, and no handle minted before the quit
resolves after it". **Why:** measured in Part 2 (`SM-1 PASS` from the recipe, `SM-1 LOG FAIL — 0 handles
retired`). **Instead of:** re-reading the existing clause to pass. **By:** Claude, for the session agent
(pre-registered rule → user ruling).
