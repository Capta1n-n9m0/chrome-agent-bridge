## 5. Proposed decisions

### 2026-10-23 · `asRef` marks through the serialiser's own `callFunctionOn`
**Decided:** `SERIALIZER_SRC` is a closure-free composite: it serialises (today's function, unchanged), then —
only when `limits.mark` is a non-empty string — runs `markFn` on the value and attaches its status as an
internal `__mark` field that the handler reads and deletes. `markFn` marks only an Element that is connected
and reachable from the top document through open shadow roots and same-origin frames, and returns
`marked | not-element | detached | closed-shadow`. The handler runs `ensureContent` first, then evaluates with a
`crypto.randomUUID()` mark; `marked` → `refOfMarked` → `ref`; a failed content call, or a lost serialiser reply
(no status and the `other` fallback envelope), runs a best-effort unmark sweep and rethrows / answers `INTERNAL`;
`not-element` (or no status with a primitive) → `BAD_PARAMS`; `detached` → `REF_STALE`; `closed-shadow` →
`BAD_PARAMS`. Without a mark the composite's output equals today's (20–22-value battery).
**Why:** F21: the objectId is released inside that callback, so the mark must ride on it, inside the session;
it keeps `debugger.ts` (outside S2's lane, FE's file) unchanged; marking after serialising means a serialiser
throw leaves no mark; the reachability check means nothing is marked that `refOfMarked` cannot find and remove.
**Instead of:** a third `Runtime.callFunctionOn` hook in `evaluateInPage` (out of lane); wrapping the user's
expression (breaks `replMode` completion values); answering a non-Element with an envelope without `ref`
(silent).
**Revisit if:** S6's SDK-5 sees a residual `data-__bridge-mark`, or `evaluateInPage` gains its own node hook.
**By:** Claude (proposed)

### 2026-10-23 · The extension's `pressKey` accepts an optional target, focused without selection
**Decided:** with `ref`/`locator`, `pressKey` resolves it, calls the new guarded content `focus(ref)` (plain
`el.focus()`), then runs today's synthetic or trusted path unchanged (the focus runs before attaching, also
with `focusEmulation`). Without a target it is byte-identical to before. The SDK surface (0.4) is unchanged.
**Why:** 0.2 and pre-registered S2.3 name pressKey; `focusForTyping` selects all, which changes what Backspace
does; FE's CDP sequence stays untouched (#88/#89; under #89's `focusFirst` the SDK focuses the tab first anyway).
**Instead of:** leaving pressKey untargeted (S2.3 would fail); reusing `focusForTyping`; an in-session focus
step for pressKey (needs `debugger.ts`/`trusted-input.ts`).
**Revisit if:** 0.4 adds a target to `Tab.pressKey`, or a live row shows the pre-attach focus is lost.
**By:** Claude (proposed; phase-doc 0.2 vs 0.4 discrepancy — for the session agent)

### 2026-10-23 · `waitFor {locator}`: validation and poll rules
**Decided:** a non-null `locator` selects the arm; with `text`, `seconds` or `networkIdle` → `BAD_PARAMS`;
`state` "visible" (default) | "hidden"; `timeoutMs` default 10 000, finite numbers rounded and clamped to
[0, 60 000], else `BAD_PARAMS`; all checked before any tab or page call. The loop runs in the service worker
(F23), polls every 100 ms without overlap, the first attempt at once; visible: found resolves, `NOT_FOUND`
polls, `AMBIGUOUS` rejects at once; hidden: `NOT_FOUND` resolves (the only resolving error), found and
`AMBIGUOUS` poll; `REF_STALE` — and an `INTERNAL` with Chrome's frame-teardown text (`Frame with ID n was
removed|is showing error page`, `No frame with id`; from code reading, unmeasured) — re-injects and polls;
any other error rejects unchanged; timeout → `TIMEOUT` (no locator text), for visible with the last
`{candidates}` as `data`; overrun ≤ one poll. The text arm keeps its page-side 200 ms poll.
**Why:** 0.2's rules plus F23's open cases; S1 measured ~1.4 s per `{text}` miss on 5 000 elements in jsdom,
so no-overlap matters.
**Instead of:** a page-side poll (throttled in hidden tabs); resolving `hidden` on any failure; overlapping polls.
**Revisit if:** S6 measures a navigation error string not covered, or the per-poll cost on a real page.
**By:** Claude (proposed)
