## 5. Proposed decisions

### 2026-10-23 · One walk function serves the snapshot and `locate`
**Decided:** `a11y.ts` `walkElements` holds the prune (`hidesSubtree`), the shadow → same-origin frame →
light order and the stop hook; `buildSnapshot` and every `locate` variant run it. **Why:** walk order and
pruning cannot drift (0.1's invariant); the pre-S1 capture passes unchanged. **Instead of:** two walks pinned
only by a cross-check test (the cross-check exists too). **Revisit if:** the snapshot needs a walk feature
`locate` must not have. **By:** Claude (proposed)

### 2026-10-23 · Locator name matching uses the snapshot's 120-character capped name
**Decided:** `{role, name}` compares against `accessibleName` exactly as the snapshot shows it (capped at 120
with `…`); substring case-insensitive, `exact` = case-sensitive equality after whitespace normalisation;
`{regex}` tested against the same string, non-stateful, invalid → `BAD_PARAMS`; `exact` ignored with a regex.
Role: exact string equality (a padded role is not trimmed — verifier NIT 4). **Why:** one name computation,
the literal invariant "what Claude saw is what matches"; "equality" in #83 read as Playwright's exact.
**Instead of:** an uncapped second name computation (a substring past char 119 would match, but the shown
name would differ from the matched one); case-insensitive `exact`. **Revisit if:** a real page needs
`exact` on a name over 120 characters. **By:** Claude (proposed; locator-rule detail #83 left open — for
user review)

### 2026-10-23 · `locate` searches past the snapshot's 800-element cap; `{css}` obeys the pruning gates
**Decided:** the 800 cap is the snapshot's output budget, not a locator rule, so `locate` walks the whole
page; `nth` counts in walk order across shadow roots and frames. `{css}` matches any element, interactive
or not, but only among elements surviving `hidesSubtree` and the zero-size gate (under layout), and reaches
open shadow roots and same-origin frames through the walk (`el.matches`); an invalid selector →
`BAD_PARAMS`. **Why:** a truncated snapshot should not make a locator miss; with hidden elements matching,
`waitFor {state:"hidden"}` (resolves on `LOCATOR_NOT_FOUND`) could never resolve for a hidden-but-present
element. **Instead of:** capping the search at 800; `querySelectorAll` over hidden elements. **Revisit if:**
a script needs to target a hidden element by CSS (it can use `evaluate` + `asRef`). **By:** Claude
(proposed; for user review — A10/F13 left these open)

### 2026-10-23 · `{text}` reads visible text, innermost over light descendants
**Decided:** an element's text = its light-DOM text nodes plus those of child elements surviving
`hidesSubtree`, whitespace-collapsed; a shadow host's text excludes its shadow root (its shadow elements
are candidates of their own); adjacent blocks join with no separator (`<div>Hello</div><div>World</div>`
reads "HelloWorld" — verifier NIT 5). Substring case-insensitive, `exact` case-sensitive equality.
Innermost = no light-DOM descendant also matches. **Why:** #83's "survives the snapshot's pruning" applied
to the text as well as the element, so hidden text never makes a parent match. **Instead of:**
`textContent` (counts hidden text); `innerText` (not in jsdom, layout-dependent). **Revisit if:** S6 finds a
real page where block joins hide a needle. **By:** Claude (proposed)

### 2026-10-23 · Locator failure data
**Decided:** `LOCATOR_NOT_FOUND {candidates: [{ref, role, name}]}` — ≤ 5 by `nearest()` (max of normalised
Levenshtein and token Jaccard, strings cut to 120 chars, ties in walk order): same-role listed elements
for `{role}`, elements owning direct visible text ranked by that own text for `{text}`, `[]` for `{css}`;
for an `nth` past the end, the first ≤ 5 matches. `LOCATOR_AMBIGUOUS {matches: [{ref, name}]}` ≤ 20 in walk
order, the total in the message. Results and candidates are `{ref: refs.add(el), role: roleOf(el) ?? "",
name: accessibleName(el)}`. Messages carry the locator's text (returned, never logged — verifier NIT 6).
**Why:** 0.1's shapes; bounded payloads; refs minted so the caller can act on a candidate. **Instead of:**
unbounded matches; an invented role ("generic") for role-less elements. **Revisit if:** S4's report wants
the ranked list for `nth` past the end too. **By:** Claude (proposed)

### 2026-10-23 · `refOfMarked` contract
**Decided:** `MARK_ATTR = "data-__bridge-mark"`; unpruned traversal of the document, open shadow roots and
same-origin frames, compared by `getAttribute` (no selector built from the mark); the attribute is removed
from every carrier on every path; one → `{ref, role, name}`, none → `REF_STALE`, several → `INTERNAL`,
non-string/empty → `BAD_PARAMS`. **Why:** F21 (shadow roots and frames), the forbidden fix "leaving the
attribute on the element". **Instead of:** `querySelector` with the mark interpolated. **Revisit if:** S2's
`asRef` needs a different not-found code. **By:** Claude (proposed)

### 2026-10-23 · `__bridgeData` is a JSON copy of `data`
**Decided:** `toMarker` sets `__bridgeData = JSON.parse(JSON.stringify(err.data))` when that succeeds and
yields an object or array; otherwise the bare marker. A `Map` therefore becomes `{}` and a `Date` a string
(verifier NIT 3; no current caller passes such data). **Why:** #82's "plain-JSON data", read as "what JSON
keeps". **Instead of:** a prototype check. **Revisit if:** a page function needs to carry non-JSON data.
**By:** Claude (proposed)
