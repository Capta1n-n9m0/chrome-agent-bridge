## 5. Proposed decisions

### 2026-10-23 · The byte-identity clause on S0's bundles is replaced by a bounded-diff clause
**Decided (proposed, contract-level: a pre-registered check, for the session agent / user):**
- Replace the S0 clause "the daemon and extension bundles are byte-identical after S0" with: `extension/dist/{content,offscreen,options}.js` are byte-identical to pre-S0.
- `daemon/dist/index.js` and `extension/dist/sw.js` may differ only by:
  - the `NO_CURSOR` entry of `ErrorCodes` and of the code set;
  - (daemon only) `isHello`'s `session` type check.
- The verifier shows this with a `diff` of the pre and post builds; anything else in the diff fails.
- Because the daemon's build id changes, the first client after S0's main-tree build hands the daemon over. This is harmless while nothing is running.

**Why:**
- S0.4 and #76 require `NO_CURSOR` in `ErrorCodes` and a guard that rejects a non-string `session`. Both are bundled: `ErrorCodes` by `daemon/src/*.ts` and `extension/src/errors.ts`, `isHello` by `daemon/src/handshake.ts:1`.
- The two pre-registered clauses cannot both hold. Measured: the diff is exactly those two changes.
- The clause's intent ("types only, no behaviour change") is kept. No existing peer sends `session`, and `fromWire` already kept any string code, so no existing peer behaves differently. The verifier read `shared/src/error.ts` and found no `isErrorCode` caller outside `shared`.

**Instead of:**
- Keeping `NO_CURSOR` out of `ErrorCodes`. That is #76's rejected option.
- Putting the `session` check in a separate guard only to dodge the clause. That games the check.

**Revisit if:** a later stage needs a true no-handover types-only stage. Then it splits the runtime constants from the types.

**By:** Claude (proposed)

### 2026-10-23 · `WaitForParams` requires `text` and carries `timeoutMs` on the locator arm (F28)
**Decided:** `WaitForParams = {text: string} | {locator, state?: "visible"|"hidden", timeoutMs?} | {networkIdle: true, idleMs?} | {seconds}` (`shared/src/protocol.ts:419`).
**Why:**
- 0.4's `{text?}` made `{}` a valid arm.
- 0.2 gives the locator arm `timeoutMs`.
- The other arms mirror today's `waitFor` handler (`extension/src/handlers/wait.ts:15-21`).

This is design-local; stage0-audit.md F28 proposed the same shape.
**Instead of:** 0.4's literal arms.
**Revisit if:** S2 or S3 needs `timeoutMs` on the text or networkIdle arm. Today both are bounded by the extension's fixed 10 s ceiling.
**By:** Claude (proposed)

### 2026-10-23 · A locator's `nth` is 0-based
**Decided:** `nth: 0` is the first match in the snapshot's walk order. It is documented at `shared/src/protocol.ts:398`, and `isLocator` accepts any non-negative safe integer.
**Why:** 0.1 and #83 leave the base unstated, and S1 needs one. 0-based matches Playwright's `nth`, which the plan models its locators on. The verifier noted (V3) that the snapshot's `frame` index is 1-based, a different field with a different purpose.
**Instead of:** 1-based.
**Revisit if:** the user prefers 1-based. In that case decide before S1 lands.
**By:** Claude (proposed; it is a locator-rule detail, so it goes to the session agent before S1)

### 2026-10-23 · `Locator` stays untagged; `isLocator` refuses mixed variants; an `undefined` key counts as absent
**Decided:**
- Keep 0.1's three-variant shape, with no `?: never` fields.
- `isLocator` (`shared/src/protocol.ts:490`) requires:
  - exactly one of `role`/`text`/`css`, as a non-empty string;
  - `name` only on role, as a string or `{regex, flags?}`;
  - `exact` only on role and text;
  - `nth` as a non-negative safe integer;
  - no other key.
- A key whose value is `undefined` counts as absent, as in the existing event guards; JSON drops such keys.
- `flags` and the regex pattern are not validated here; S1 owns that failure.

**Why:** 0.1 is a contract. Mixed locators arrive untyped from the MCP and from raw `call()` anyway, so the runtime guard is where they must be refused.
**Instead of:** an exclusive union with `never` fields, which would change 0.1's text.
**Revisit if:** S3 wants compile-time rejection for SDK users. That change is additive for valid locators.
**By:** Claude (proposed)
