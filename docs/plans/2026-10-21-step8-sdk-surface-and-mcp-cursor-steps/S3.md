## 4. Deviations from the phase doc

- `BridgeClient.close()` keeps closing the client; `close` is the one Tab method not mirrored on the
  client (0.4 says "every `Tab` method mirrored"; the name collides with Step 6's `close()`). §5.
- `tabs()` returns `current: boolean` instead of 0.4's `active`, per 0.4's own corrected note and #43.
- `Tab.scroll`'s `direction` is `"up" | "down"` (0.4 gives no type; the extension implements only
  these).
- `evaluate` returns `envelope.value` (undefined for non-JSON kinds; nodes need `evaluateRef`), the
  literal 0.4 rule; page throws arrive as `PAGE_ERROR` from the extension.
- `newTab`/`claim` capture the generation before sending: an answer that races a 4002 close throws
  `TAB_UNKNOWN` and leaves the cursor alone (not in the brief; stricter). §5.
- `Tab`'s constructor is public in TypeScript (the class is exported); documented as internal.
- The policy is injectable through the `Tab` constructor's 4th argument for tests; not exported.

## 5. Proposed decisions

### 2026-10-23 · S3's `Tab` surface details
**Decided:** (1) `BridgeClient.close()` keeps its Step 6 meaning (close the client); the client mirrors
every `Tab` method except `close`, and the cursor tab is closed with `client.tab().close()`.
(2) `tabs()` entries are `{handle, title, url, owner?, current}`, `current` read only from `listTabs`'
`current` (#43). (3) `scroll` takes `direction: "up" | "down"`; anything else is a local `BAD_PARAMS`.
(4) `evaluate` returns `envelope.value`; `evaluateRef` throws `BAD_PARAMS` when no ref comes back (with a
reload hint for `kind:"node"`). (5) The call `timeoutMs` of `waitFor` is the wait's own bound + 5 s
(locator `(timeoutMs ?? 10000)+5000`, seconds `s·1000+5000`, text/networkIdle 15 000), of `evaluate`
the page timeout + 5 s (F22). (6) Local validation (`normalizeTarget`, `scroll`, `waitFor.seconds`)
throws the shared `BridgeError(BAD_PARAMS)` with no call.
**Why:** (1) the MCP and Step 6 tests call `client.close()`; renaming it breaks every existing caller.
(2) 0.4's corrected note and #43. (3) the content script's `scrollRef` scrolls down for any value but
`"up"` and answers ok (verifier finding 1). (5) a 45 s wait met the 30 s default call (stage0-audit F22).
**Instead of:** mirroring `close` (would shadow the client's close); keeping `active` in `tabs()`;
`left/right` silently scrolling down; a default call timeout for waits.
**Revisit if:** S5/S6 shows a script needing horizontal scroll or a non-JSON `evaluate` value.
**By:** Claude (proposed; (1) and (2) touch the SDK's exported surface — for user review)

### 2026-10-23 · The SDK cursor is changed only by newTab/claim and a 4002 reconnect — for user review
**Decided:** built to the literal 0.4 rule: `release()`, `close()` and a `tabGone` event leave the
cursor in place; the next call on it gets the daemon's answer (`TAB_GONE` after a close or retire; an
unheld-tab call after a release). The cursor and generation are reset synchronously at the top of the
4002 branch of `handleClose`, before pending calls are rejected and before the reconnect knock, so a
call queued behind the reconnect or arriving in the same `ws` read already sees them (F24). A
tab-minting answer that races a 4002 close yields `TAB_UNKNOWN`, never a stale `Tab`.
**Why:** the cursor rule is contract-level and 0.4 names only newTab/claim/4002; the early reset is
stricter than "after the reconnect".
**Instead of:** clearing the cursor on the client's own `release()`/`close()` of the cursor tab or on
`tabGone` (a friendlier local `NO_CURSOR`, and no call on an unheld tab after `release()`) — the
user's choice, since it changes the cursor rule.
**Revisit if:** S6 shows a script acting on an unheld tab after `release()`.
**By:** Claude (proposed — for user review)
