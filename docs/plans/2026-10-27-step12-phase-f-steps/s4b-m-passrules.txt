Step 12 S4b measurer — pass rules, written 2026-10-28 before any measurement ran (agent-rules §2). Not edited after the run.

Setup: a scratch branded Chrome on its own fresh temp profile (--user-data-dir under %TEMP%\claude\s12-s4b-m), the
Stage 0 m2 method (stage0-m2-setup.txt): probes loaded over --remote-debugging-pipe Extensions.loadUnpacked, driven by
Runtime.evaluate in the probe's service worker over a scratch CDP port. Probe P = the product manifest's permissions
(as m2's P). Probe Q = a second extension with debugger + tabs. Fixture: python http.server on 127.0.0.1, free port.

== (1) CON-KEPT ==
Per repetition: a fresh background tab loads con.html, whose own script, before any attach, logs N=10 console.log
lines "pre-0".."pre-9" and throws one uncaught error (Error "pre-err", from a setTimeout). After load + 500 ms, P:
  attach (ONE session) ->
  R1: Runtime.enable, collect Runtime.consoleAPICalled / Runtime.exceptionThrown for 500 ms, Runtime.disable ->
  while disabled: the page logs "mid1-0".."mid1-2" (chrome.scripting MAIN world; no debugger command) ; wait ~1 s ->
  R2: Runtime.enable in the SAME session, collect 500 ms, Runtime.disable ->
  while disabled: the page logs "mid2-0".."mid2-2"; wait 5.1 s ->
  R3: Runtime.enable in the SAME session, collect 500 ms, Runtime.disable ->
  control R4: detach, attach a NEW session, Runtime.enable, collect 500 ms, Runtime.disable, detach.
Also recorded per read: how many of its events arrived within 100 ms of the enable reply (the product's
CONSOLE_SETTLE_MS), the exceptionIds, and the per-message timestamps.
A message's identity: event kind + type + text (first arg value / exception description first line) + timestamp.

Pass rule CK-1 ("replay holds", 1 s pause): in a repetition, R2 contains every message R1 delivered, with identical
  identity (timestamp equal), in the same relative order. Holds = 5 of 5 repetitions. Any other result = does not hold
  (the count is reported as measured).
Pass rule CK-2 ("replay holds", 5.1 s pause): the same comparison R1 vs R3. Holds = 5 of 5.
Recorded, no pass rule (a fact for the product): whether "mid1-*" appear in R2 and "mid1-*"+"mid2-*" in R3 (count and
  order, timestamps between the reads); whether exceptionId changes between reads; R4 vs R1 (the C7 control).
CK-0 control (validity): R1 must deliver all 10 "pre-*" and the 1 uncaught error. If R1 misses any in a repetition, that
  repetition is INVALID (reported, not counted as pass or fail) and one replacement repetition runs, as a new row.

== (2) SWEEP-HELD ==
Per repetition: a fresh background tab Y loads fx page; Q attaches chrome.debugger to Y and sends Runtime.evaluate "1+1"
(control: must answer 2; else the repetition is INVALID). Then P (which holds no session on Y):
  a) chrome.debugger.getTargets(): record Y's entry (attached, type, whether extensionId is set and whose: P/Q/other).
  b) chrome.debugger.detach({tabId: Y}): record ok, or the exact error message text.
  then Q: Runtime.evaluate "2+2" on its session (must answer 4), and Q's onDetach events for Y since the attach.
  then P getTargets again (Y's attached), then Q detaches (cleanup).
Pass rule SH-1 ("no side effect"): Q's next command after P's detach succeeds (answers 4) AND Q received no onDetach for
  Y, 5 of 5 repetitions. Any other result = side effect (reported as measured).
Recorded, no pass rule: the exact detach error text (5 of 5 identical or not); what getTargets' `attached` reads.

Variant SH-2 (other client = DevTools, if it can be opened): the same, with DevTools opened by F12 (UIA/SendKeys only on
the scratch Chrome's window) on an active tab Y and no Q session. Survival read: the DevTools frontend target is still
listed over the scratch CDP port after P's detach, and P's getTargets still shows Y attached. If DevTools cannot be
opened this way, SH-2 is NOT MEASURED and said so. The scratch Chrome runs with --enable-unsafe-extension-debugging (the
m2 method; the probes cannot be loaded otherwise), which is stated with every SH-2 reading.
Pass rule SH-2: DevTools still attached after P's detach, 5 of 5 (or NOT MEASURED).

Variant SH-3 (other client = a raw CDP client over the scratch --remote-debugging-port, attached to Y's page target by
Target.attachToTarget flatten): the same as SH-1, the client's next command Runtime.evaluate "3+3" must answer 6 and
it must get no Target.detachedFromTarget for its session. Pass rule SH-3: 5 of 5. (Recorded as a stand-in for a
DevTools-like client; not the product's case.)
