## 6. Findings

**H1 — MINOR — The banner rule's "every failing clause" set is narrower than the verdict's, and its fail-safe direction is
unpinned** (`recipes/s12-r18-lib.ps1:19, 21, 48-49`).

**The narrow set.** `Get-R18Verdict` counts a `ROW` line whose label has up to three tokens (`$R18VerdictRe`). The `ROW`
branch of `$R18BadRe` accepts only a one-token label. So a non-banner `ROW <a> <b> FAIL: …` beside banner-only clause
lines makes the verdict FAIL but is not in `$bad`, and the row converts to NOT MEASURED.

Evidence: `bv3.ps1` case `latent multi-token ROW`, which reads `verdict=FAIL banner verdict=NOT MEASURED …`.

This cannot happen with today's lines. Inside these row blocks, `up6` prints `ROW R17-UP-6`, `raw` prints `ROW F-RAW*`,
and the drivers print only `Say9` lines (`idle wait`, `IDLE`, `SAMPLER`).

**The unpinned direction.** Two mutants survive:
- W6: a FAIL with no recognised clause line converts. The real code keeps it FAIL, which is the safe direction for any
  future wording change, but no test pins it.
- W3: the LEAKS requirement applies only to a bare `ROW F-RAW `, so leaky F-RAW-2 and F-RAW-DIR rows convert. The real
  `'ROW F-RAW'` prefix covers them, but no fixture has a leaky F-RAW-2 or -DIR.

**Suggested fix:**
- Take `$bad` as every line that `$R18VerdictRe` reads as non-PASS, plus the CHECK form. Or give the ROW branch the same
  `(?: \S+){0,2}?` label.
- Add three fixtures: a FAIL whose lines match no clause form (stays FAIL), `rawLines("F-RAW-2", win(true), clean, 2)`
  (stays FAIL), and a multi-token non-banner ROW FAIL beside a banner clause (stays FAIL).

**NITs.**
- n-d: mutant W7 survives. It reads only FAIL clause lines and ignores NOT MEASURED ones. It is equivalent for today's
  helpers, because the only NOT MEASURED result `refusalStepJudge` can give is the unsampled-banner one, which converts
  anyway. No action.
- n-b and n1 (F3z, V12) still survive, as verifier 2 recorded. Both are harmless.
