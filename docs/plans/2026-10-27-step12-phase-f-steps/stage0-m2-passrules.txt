D — kept debugger session
- D1 (attach cost). Fixture tab on A, in the background. Fresh: n=20 of {attach; sendCommand Runtime.evaluate "1"}
  timed from before attach to the reply, then detach (not timed); also the attach alone recorded. Kept: one attach, then
  n=20 sendCommand Runtime.evaluate "1" timed each; detach. Reading: medians and max of each; "attach cost" = median(fresh)
  - median(kept). No pass/fail; a record.
- D2 (banner with a kept session). Banner = any UIA element in a scratch-Chrome window whose Name contains
  "started debugging this browser" (the bridge sampler's test, recipes/s9-win.ps1 Test-S9Banner); sampled continuously
  (each sample starts when the previous ends, its start and end time recorded), from 3 s before attach to 30 s after
  detach. Session held 30 s, one Runtime.evaluate every 5 s. 3 repetitions, >= 60 s apart is not required (each starts
  after the previous one's 30 s tail).
  Reading "shown continuously while attached": from the first positive sample after the attach to the detach, every sample
  is positive (count the negatives; any negative = "not continuous", with its times). Reading "goes after detach": gone
  between the last positive sample after detach and the first negative one (stated as an interval). "Never shown" if no
  sample positive in the attached window. The appear delay = first positive sample start minus attach resolved.
- D3 (onDetach reasons). chrome.debugger.onDetach recorded with reason and time.
  (a) kept session, the tab closed by chrome.tabs.remove: reading = the reason string received within 5 s, or "none".
  (b) kept session, the banner's Cancel button pressed by UIA Invoke (InvokePattern; a button named "Cancel" inside the
      scratch window, nearest the banner text): reading = the reason within 5 s, or "none"; the next sendCommand result.
  (c) kept session on tab X, X made active and the scratch window foreground, DevTools opened by the keyboard (F12, then
      Ctrl+Shift+I if no DevTools window appears within 3 s): reading = onDetach reason within 10 s or "none (coexists)";
      then a sendCommand on the kept session: ok or the error text; then (if still attached, after detach) a new attach:
      ok or the error text. Then DevTools closed by the keyboard (F12 / Ctrl+Shift+I to its window) and attach again:
      ok or error. (c') DevTools opened first on a tab with no session, then attach: ok or the error text.
  "DevTools opened" is confirmed only by a new scratch-Chrome window whose title starts with "DevTools", or by
  chrome.debugger.getTargets/CDP showing it; if neither, (c) is NOT MEASURED (keys may not have reached Chrome).
- D4 (survival). Kept session on tab X (A). (a) same-origin navigation by chrome.tabs.update(url A/...?n=2), wait load;
  (b) cross-origin navigation to B, wait load; for each: onDetach events seen (reason or none), then sendCommand
  Runtime.evaluate "location.port" : ok with the new port = "survives and talks to the new document"; error = "lost" with
  the text. (c) worker restart: the way the worker is stopped is recorded (first try CDP ServiceWorker.stopWorker through
  an extension page; else Target.closeTarget of the worker target; else NOT MEASURED, never waited culling with a held
  CDP client); after the new worker starts: chrome.debugger.getTargets() 'attached' for X, the banner (one UIA sample
  each second for 10 s), a sendCommand {tabId:X} without attach: ok = "survives", error text = "not usable", and an attach:
  ok or "already attached" error text.

E — native file chooser (fixture page A/fx.html: <input type=file id=f style=display:none>, <button id=b> whose onclick
calls f.click(), <button id=sofp> calling showOpenFilePicker(); counts change events and records file names/sizes)
- Native dialog = a top-level window of the scratch Chrome browser PID with class "#32770", sampled every <= 300 ms from
  the click to 3 s after; any found is closed by its Cancel button (UIA Invoke) or WindowPattern.Close and recorded.
- Background: the fixture tab X is not active; another tab in the same window is active (checked by chrome.tabs.get
  before every click; a click with X active is a set-up failure G-0).
- E1: sendCommand Page.setInterceptFileChooserDialog {enabled:true} on an attached tab: result "{}" = accepted, error text =
  refused. Done with and without Page.enable first.
- E2: intercept on (both with and without Page.enable), Runtime.evaluate {expression:"document.getElementById('b').click()",
  userGesture:true}; n=5 per variant; reading per sample: Page.fileChooserOpened received on chrome.debugger.onEvent for
  {tabId:X} within 5 s (yes/no, ms, mode, backendNodeId present, frameId present); native dialog yes/no. Same for #sofp
  (showOpenFilePicker), n=3, with Page.enable.
- E3: after each E2 event with a backendNodeId: DOM.setFileInputFiles {files:[fixture file], backendNodeId}: result ok/error;
  then the page's change count increment and the file name and size seen by the page (read by chrome.scripting MAIN).
  Reading "page receives the file" = change +1, name and size equal the fixture's.
- E4: (i) interception switched off (enabled:false) on the same session, userGesture click: native dialog yes/no (closed
  by us), fileChooserOpened yes/no; n=2. (ii) intercept on, detach, attach again without enabling, Page.enable, click:
  native dialog yes/no, event yes/no; n=2. Reading "interception ends with the session" = (ii) shows a native dialog.
- E5: intercept on, Page.enable, Runtime.evaluate click WITHOUT userGesture: event yes/no, native dialog yes/no, n=3;

- E6: intercept on, Page.enable, a trusted Input.dispatchMouseEvent (mousePressed+mouseReleased, left, clickCount 1) at
  the button's centre (getBoundingClientRect), X in the background: event yes/no, native dialog yes/no, page click seen,
  n=3.
- E fact "E on one call's own session" = E2 with Page.enable shows the event on the same session in >= 4 of 5 samples.

G2 — the settle pause after a trusted input (scratch window W1 with tabs T and H; a second scratch window W2)
- G2a: n=20: H active in W1 and W2 focused (set before each sample), then chrome.tabs.update(T,{active:true}) and
  chrome.windows.update(W1,{focused:true}); t0 = both resolved. Page T records visibilitychange->visible and window
  focus times. Reading: medians and max of (visible - t0) and (focus - t0); the count of samples where the event came
  before t0 (negative) or never within 2 s ("none") is reported.
- G2b: T active and focused, kept session. n=20 mouse: Input.dispatchMouseEvent pressed+released at #clk; t_reply = the
  released reply; page: click handler time, then the first requestAnimationFrame after it. n=20 key: dispatchKeyEvent
  keyDown{text:"a"} + keyUp into #t; page: keydown and input handler times, the first rAF after input. Reading: medians
  and max of (handler - t_reply) and (rAF - t_reply); negative = the handler ran before the reply returned.
- G2c: T active, #t focused, kept session on T; 10 keys "abcdefghij" by dispatchKeyEvent (awaited one by one); then
  chrome.tabs.update(H,{active:true}) after d ms, d in {0,50,100,250,500}, measured from the last key's reply (c1, n=20
  per d) and from the first key's send (c2, n=10 per d, the switch lands mid-typing). After 1 s: chars in T's #t and
  keydowns seen by H. Reading: lost = 10 - received in T; misrouted = keydowns in H.
- G2 bound (derived after, from these rules only): the smallest d in the list at and above which c1 AND c2 show 0 lost
  and 0 misrouted in every sample, and the max of G2b's (rAF - t_reply); the pause the data support = the larger of the
  two, stated against 500 ms (#321). If loss or misroute occurs at 500 ms, "500 ms not supported". If no loss at any d,
  the bound is set by G2b alone and the statement says the switch never lost input in this machine's runs.
