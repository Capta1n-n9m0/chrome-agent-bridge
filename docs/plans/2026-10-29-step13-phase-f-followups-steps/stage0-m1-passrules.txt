and appended below before any new leg.

Setup (both legs): branded Chrome from <chrome> (version read from the install folder and CDP Browser.getVersion),
--headless=new, its own fresh --user-data-dir under <scratch>, --remote-debugging-pipe (no port),
--enable-unsafe-extension-debugging, probes loaded by CDP Extensions.loadUnpacked. Events are recorded inside the probe's
service worker with one clock (performance.timeOrigin + performance.now()) and a dispatch sequence number.

== G1-order (probe G: the product manifest's permissions + webNavigation) ==
Fixture: http://127.0.0.1:<port>/ on a free port in 8080-8085. One window, tabs H (fx.html?h) and O (fx.html?o).
Leg fg: O active before each trigger. Leg bg: H active, O inactive before each trigger.
Kinds per leg (the trigger is a CDP Runtime.evaluate with userGesture:true on the opener's page target, from the driver,
not from the probe): wo = window.open(url,"_blank"); woNo = window.open(url,"_blank","noopener"); wf = window.open(url,
"_blank","popup,width=400,height=300") (a new window); lk = click on <a target=_blank>; lkNo = click on <a target=_blank
rel=noopener>; pp = popup of a popup (O opens P1 by wo; for leg bg H is made active again; then P1 opens P2 by wo; the
sample is P2, its expected source is P1). 4 samples per kind, so 24 per leg. Plus kind blk = window.open with no user
gesture (3 per leg; expected blocked; not counted toward the 15).
Per sample, recorded: which of tabs.onCreated (C) and webNavigation.onCreatedNavigationTarget (N) came first; delta
t(N) - t(C) in ms; N.sourceTabId vs the expected opener; C.openerTabId (O, H, P1, undefined, other); a later tabs.get
openerTabId; whether either event is missing within 3000 ms of the trigger.

R1 Valid sample: a new tab's C or N arrives within 3000 ms of the trigger. Exit check: >= 15 valid samples in each leg
   (fg, bg); else that leg is NOT MEASURED.
R2 sourceTabId hit: N.sourceTabId === the expected opener's tab id. Reported as hits/valid per leg and per kind.
R3 Order: reported as counts C-first / N-first / C-only / N-only per leg and kind. No rule on which is expected.
R4 The join bound, decided from all valid samples of both legs (all kinds but blk):
   D = max |t(N) - t(C)| over samples with both events.
   - "One field" is proposed only if every valid sample has both events AND D <= 250 ms; the proposed bound is the
     smallest of 250 / 500 / 1000 ms that is >= 4 x D.
   - Else ("late event"): any valid sample with one event missing, or D > 250 ms. The report says which.
   - If N comes first in any sample, the report says the join must buffer in both directions (a fact, not a failure).
R5 blk: recorded as observed (a tab or not; C or N or neither). No pass/fail.

== G1-reload (probes Ra and Rb: exactly the product manifest's permissions; observer M: "management") ==
Readings: M's chrome.management.get(id) {enabled, disabledReason, permissions}; M's management.onEnabled/onDisabled/
onInstalled events; from a chrome://extensions page target, chrome.developerPrivate.getExtensionInfo(id) {state,
disableReasons, permissions.simplePermissions} and the item card's text; the set of page targets before and after
(a new tab, window or dialog target counts as a prompt sign).
Warnings: M's chrome.management.getPermissionWarningsByManifest(text) on the product's extension/manifest.json text as
it is at ff121a4, and on the same text with "webNavigation" appended to permissions.
Each reload path is first run with the manifest unchanged (control), then with webNavigation added:
   path A: chrome.runtime.reload() evaluated in the probe's own worker (probe Ra);
   path B: the chrome://extensions reload button (#dev-reload-button of the probe's card, developer mode on) (probe Rb).
R6 "Stays enabled with no prompt" for a path = 3 s after the +webNavigation reload: management.get.enabled === true, no
   disabledReason, developerPrivate state ENABLED with every disableReasons flag false, no new page target. Reported as
   YES / NO (with the reason fields as read).
R7 Discrimination: if the control reload of a path does not stay enabled by R6's test, that path's +webNavigation
   reading is NOT DISCRIMINATING for the permission question (a reload artifact of the flag/CDP load); the report then
   compares the two readings' reason fields and says so.
R8 "Warning list changes" = the two getPermissionWarningsByManifest arrays differ (compared as ordered string arrays);
   the added strings are quoted.
R9 Flagless control: the same profile relaunched without --enable-unsafe-extension-debugging; if the CDP-loaded probe is
   not present there (developerPrivate.getExtensionsInfo), the flagless reload is NOT MEASURED.
