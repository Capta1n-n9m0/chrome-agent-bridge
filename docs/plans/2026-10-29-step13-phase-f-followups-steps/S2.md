## 5. Proposed decisions
### 2026-10-29 · S2: a hand-written writer produces the envelope's text, so page `toJSON` hooks never reach `value`
**Decided:**
- `SERIALIZER_JSON_SRC` writes the envelope with `envelopeJsonFn`.
- `JSON.stringify` runs on primitive values only, so no page `toJSON` is called and nothing in the page is changed.
- `__mark` must be present exactly when the call asked for a mark.
- The fallback covers only a page that replaces a global: a replaced or throwing `JSON.stringify` ends in the fallback.

This narrows #386's "a hooked envelope falls back", and it replaces the builder's proposal to accept a forged envelope.

**Why:** a harmless prototype hook in the style of Prototype.js otherwise changed `value` silently (S2-verifier F1). A
forged or dropped `__mark` changed the reply's shape or left a mark in the page (F2, F3).

**Instead of:**
- An own `toJSON: undefined` on each object in the envelope. It is safe today, but it changes objects and depends on
  the page's `Object.defineProperty`.
- Falling back on any hook, which would lose a correct value.

**Revisit if:** a page that replaces `Object.keys`, `Array.isArray` or `JSON.stringify` is found to make the extension
act beyond returning a wrong value. That exposure is older than S2 (S2-verifier2 N2).
